# MIR AOT — ELF `.o` / executable output + debug integration (implementation plan)

**Status:** DESIGN (2026-07-19). Owner decision 2026-07-18: AOT pulled forward
from ADR 0001's downstream list as a MIR-fork feature (ELF relocatable objects
and executables generated by MIR itself), folded together with the
`cyanogilvie/debug-support` integration that was previously a separate
cherry-pick-eval track (`reference_mir_debug_support`).

**Why now:** `-o` is an asmjit-master capability (the promote-parity memory
includes it); on the CIR backend the flags exist but stub out
(`madc.cpp:808` — "AOT ... not available on the CIR backend; emit C with
--emit=c11"). This work restores first-class native output without an external
toolchain, and its debug half gives source-level gdb on the JIT lane as a
byproduct. It does NOT gate on (and does not compete with) the gcc-torture
class-(a) promote burndown — different surfaces (fork gen layer vs madc front
end).

## Goals

1. `madc --emit-object x.o` — a real ELF64 relocatable object from the CIR →
   c2mir → MIR pipeline, written by MIR itself (no gcc/clang involved).
2. `madc -o prog` / `--emit-executable` — a runnable executable (link step
   drives the system `cc` initially, like every compiler driver).
3. Debug end-to-end: `.symtab` + DWARF (`.debug_line`, then locals/types) in
   the `.o`, AND gdb source-level debugging of JIT'd madc programs via the GDB
   JIT interface — both powered by the one `mir-debug` builder.
4. Design for upstream (Tier-3 discipline): the object-mode + ELF writer as an
   upstreamable MIR feature; the debug branch is already Makarov-styled.

## Non-goals

- Replacing `--emit=c11` — it stays the first-class portable-AOT and
  performance lane (gcc/clang -O2). MIR-native `.o` is about self-containment.
- New codegen. `MIR_gen`'s existing x86-64 output IS the code; AOT changes
  packaging only (memory publication → sections + relocations).
- Non-x86-64 ELF targets (aarch64 later; Mach-O is Track 6.3's own item).
- A custom linker. Executables link via the host `cc` driver first; direct-ld
  is a stretch rung.
- `_BitInt`, PIC/shared-object output (text relocs are fine in a `.o` destined
  for an executable; a `-fPIC` analogue is a later rung if ever needed).

## Verified facts (recon 2026-07-19, fork @develop 4ad333dc)

1. **Gen already tracks every address that escapes into code** — the reloc
   ledger practically exists (mir-gen-x86_64.c):
   - **Call address pool** (`P` template, :755, :1520): calls are
     `call *disp32(rip)` through 64-bit slots in a per-func memory pool;
     `store_call_ref`/`call_refs` (:3212–3275) record slot addresses for the
     func-redef machinery. AOT: the pool becomes a GOT-like section; each slot
     gets `R_X86_64_64` against the callee symbol; the disp32 becomes a PC32
     reloc to that section.
   - **Const pool** (`c` template, :769, `add_to_const_pool` :2547):
     rip-relative 64-bit constants. Pure values stay verbatim in `.rodata`;
     R0 must survey which entries are item ADDRESSES (those need relocs).
   - **`abs_address_locs`** (:772): imm64 addresses embedded in code text →
     `R_X86_64_64` text relocs against the item's symbol.
   - **Switch tables** (`T`) and label refs: rip-relative, section-internal —
     no external relocs.
2. **Imports** resolve at `MIR_link` via `import_resolver` (mir.c:2178,
   dlsym-style) or `MIR_load_external`. In AOT they become undefined symbols;
   the system linker does what the resolver did. madc's runtime surface
   (extern-C `__madc_*` helpers, exception runtime, mangled-direct libstdc++
   symbols, libc) all resolve at link against `libmadc` + `-lstdc++` etc. —
   cleaner than the JIT's RTLD_DEFAULT scan.
3. **`cyanogilvie/debug-support`** adds exactly three files not in fork
   develop — `mir-debug.h` (138), `mir-debug.c` (822), `mir-debug-gdb.c`
   (138) — plus mir.h/mir-gen plumbing: `MIR_set_source_loc` (file_id, line
   stamped on insns), `MIR_func.line_map` (code-offset → source-loc, filled by
   MIR_gen), `MIR_reg_frame_offset`. The API builds **an in-memory ELF object
   with `.symtab` + `.debug_line` + `.debug_info`** (type graph: base /
   pointer / array / struct; locals with frame offsets) and registers it via
   the GDB JIT interface. c2mir is a reference consumer (stamps source locs).
   The branch tip (66295af4) sits one commit off a develop-content base.
4. **mir-debug.c already contains an ELF writer** (in-memory, for the gdb
   protocol). The AOT writer extends this one implementation — sections,
   symtab, DWARF encoders are shared, per no-parallel-implementations.
5. **Upstream's existing "AOT"** is `b2ctab` + `mir-bin-driver.c`: embed
   binary MIR as a C table, JIT at startup with a canned resolver. REJECTED as
   the primary (still JITs at runtime, no real `.o`, no static linking, needs
   a C compiler anyway) — noted as the zero-fork-work fallback.
6. **madc side:** `--emit-object` / `--emit-executable` / `-o` already parse
   (madc.cpp:543–546) and error at :808. `scripts/run_tests.sh --exe` exists
   and is currently dead on CIR — it becomes the AOT arbiter.
7. **ODR/linkonce:** multi-TU `--project` uses `MIR_set_func_redef_permission`
   as the linkonce analogue. ELF has the real mechanism: emit such functions
   as **weak** symbols (or COMDAT groups later) — the AOT mapping is more
   natural than the JIT's.

## Design

### D1 — object-capture mode in gen (the invasive half)

A new generator mode (`MIR_gen_set_object_mode(ctx, 1)`-style), x86-64 first:

- Code is captured per function instead of `_MIR_publish_code`'d; nothing is
  patched with live addresses. The four escape categories above are recorded
  as `(section, offset, kind, target-item-or-import, addend)` reloc entries.
- Per-func const pools concatenate into `.rodata`; call-address pools into a
  `.mir.addrpool` progbits section (reloc'd per slot); code into `.text`.
- **Data items:** `MIR_data_item` → `.data`/`.rodata`; `MIR_bss_item` →
  `.bss`; `MIR_ref_data_item` (address-valued data — madc's vtables, typeinfo,
  global-init function tables) → `R_X86_64_64` data relocs; `expr_data` policy
  decided in R0 (evaluate at emit vs reject with a clear error).
- **Symbols:** export items → `GLOBAL`; import items → `UNDEF`; module-local
  → `LOCAL`; redef-permitted (linkonce) → `WEAK`.
- Mode OFF = today's JIT behavior, byte-for-byte — the mode is additive and
  CI-visible (R2 gate runs both).

### D2 — one ELF writer

Factor `mir-debug.c`'s in-memory ELF emission into a shared core serving BOTH
consumers: the GDB-JIT in-memory object (existing) and the on-disk relocatable
`.o` (new: `.text/.rodata/.data/.bss/.mir.addrpool` + `.rela.*` + full
symtab). One writer, one section/DWARF encoder — no parallel implementation.

### D3 — debug integration

- **R1 first, independently valuable:** merge debug-support into fork develop
  (three files + plumbing; the branch base is already develop-shaped). madc
  gains `-g` on the JIT lane: stamp source locs from cir_node file/line
  through c2mir → `MIR_debug_*` → `MIR_debug_gdb_register` → `break
  file.mad:42` works in gdb on JIT'd code. `-g` implies gen opt 0, no inline,
  spill-all (the header's documented debuggable-code recipe).
- **AOT lane:** the same `MIR_debug_t` object feeds the `.o` writer —
  `.symtab` function symbols + `.debug_line` land with R4/R5; locals/types
  (`.debug_info`) ride the same builder when `-g`.

### D4 — madc integration

- `--emit-object`: normal pipeline, gen object mode, write the `.o`. One `.o`
  per TU; `--project` loops TUs (combined-module option later).
- `-o` / `--emit-executable`: emit temp `.o`, link via host `cc`:
  `cc x.o -o prog -L<libdir> -lmadc -lstdc++ -lm -ldl -lpthread [-lzstd]`
  (+rpath or `--static-madc` linking `libmadc.a` for a hermetic binary —
  default decided in R4 by measuring; the embedding/sandbox story favors
  static). `main` + `__madc_global_init` are already in the module.
- `scripts/run_tests.sh --exe` flips live: every green JIT test must compile,
  link, run, and byte-match the JIT lane. That is the AOT arbiter.

## Rungs (each lands with its own gate; fork pin discipline throughout)

- **R0 — survey (fork, no behavior change).** const_pool address-vs-value
  provenance; every `abs_address_locs` producer enumerated; item→section/
  symbol mapping table written; `expr_data` policy; TLS/thread-local check;
  confirm c2mir's source-loc stamping state on the branch. Output: survey
  notes appended here.
- **R1 — debug-support merge + madc JIT `-g`.** Gate: gdb `break file:line`,
  named frames, `info locals` on a `.mad` test via the JIT; fulltest
  unaffected; `MIR_COMMIT` bump in the same madc commit.
- **R2 — object-capture mode in gen (x86-64).** Delivered with a `c2m -c`
  flag so it is testable inside the MIR repo (upstream-facing). Gate: a
  mir-tests/c-tests subset compiles to `.o`, links with gcc, runs == JIT
  output; JIT lanes byte-identical with mode off; c2mir-test suite green.
- **R3 — ELF-writer unification.** mir-debug's gdb object and the `.o` writer
  share one core. Gate: R1 and R2 gates both stay green off the shared code.
- **R4 — madc `--emit-object` + `-o` link driver.** Gate: full madc suite
  under `run_tests.sh --exe` green and byte-identical to the JIT lane; packed
  arbiter unaffected; `-o` parity line item closed against asmjit-master.
- **R5 — DWARF in the `.o`.** `.debug_line` first, locals/types second.
  Gate: gdb `break file:line` + `bt` names in an AOT executable.
- **R6 — stretch, in any order:** gcc-torture through the AOT lane; direct-ld
  experiment; aarch64 object mode; PIC mode; COMDAT groups.

## Risks / open questions

- **Redefinable functions:** weak-symbol mapping needs the R0 survey to
  confirm every redef consumer (pattern serves, `--project` ODR) is
  emit-final by AOT time.
- **expr_data**: if madc/c2mir emit any, the evaluate-at-emit path must match
  MIR_link semantics exactly — else reject loudly (no silent divergence).
- **Lazy generation:** AOT gens every function eagerly; interaction with the
  forest lazy-materialize lane means AOT forces full materialization (fine —
  it is a batch compile), but measure compile time on SMAUG.
- **Text relocations** from `abs_address_locs` are legal in a `.o`/static exe;
  the count should still be surveyed — if dominant, prefer routing those
  through the addrpool instead (quality, not correctness).
- **Fork divergence:** ~2–4k lines estimate. Mitigation: `c2m -c` makes it a
  self-contained upstreamable feature; PR upstream after R4 proves it.
