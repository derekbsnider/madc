## 3. The correction that matters (#64)

The pre-compaction chain said the darwin forest held only `<iosfwd>`'s **forward
declaration** of `ios_base`. **That was wrong.** `ios_base`'s full definition was
recorded from `.../v1/ios` all along; only the FIRST `--dump-forest` rows are
`iosfwd`, and the earlier read stopped there.

What it actually was: a **class-nested enum tag was STAMPED a forest type-id but
never RECORDED**. `[basic.scope.class]/1` makes such a tag a member, so
`TokenENUM::parse` deliberately keeps it out of `datatype_map` (the guard that
stopped `money_base::part` leaking `part` to file scope) — and the freeze's
enum-recording walk read exactly that map. `forest_serialize_type_id` had
already stamped the tag an id as a cross-reference, so the id resolved to a
`DK_NONE` record. `std::ios_base` carries `event_callback *__fn_` whose
signature takes `ios_base::event`; at bind the fn-ptr could not be rebuilt,
`__fn_` would not swizzle, and pass 2's `if (!ok) continue;  // defensive: the
closure should have dropped it` dropped the aggregate **silently**. Members
flatten from bases → **11 aggregates** died on one member.

**Lesson worth keeping: two optimistic assumptions met one silent failure.**
`arena_chain_ok` returns true for a `DK_FPTR` chain unconditionally ("the target
signature never gates member layout"), so the closure never dropped it; and the
fill's own bail had no diagnostic. Neither was wrong alone.

## 4. NEXT WORK — UFCS for the madc dialect (task #66) ← START HERE

**The owner chose this as the next task and approved the design** ("looks good",
2026-08-17). Full plan: **`docs/plans/2026-08-17-ufcs-madc-dialect.md`** — read
it before touching anything; what follows is the index.

Ruleset, owner's own words:

```
x.f(y)  -> viable member f?         use it -> otherwise ordinary f(x, y)
f(x, y) -> viable declared free f?  use it -> otherwise x.f(y)
                                           -> otherwise existing unresolved-symbol behavior
```

Member-first for dot, free-first for call syntax. **One fallback each, fixed
order, no merged overload set, no cross-kind ranking** — the D/Nim rule, NOT
C++ N4165. That is precisely why this needs **no overload-resolution surgery**.
If a slice starts wanting to touch ranking, STOP: the rule has drifted.

**The safety property — hold it and test it.** Phases 1–2 fire ONLY where madc
today raises a hard error (`Unidentified member 'f' in 'T'`, `member reference
is not a structure or union`). No program that compiles today can change
meaning.

Hooks verified at `e9e92af9`, `src/parser.cpp` — the dot path is one contiguous
decision at ~33066–33266:

| line | site | slice |
|---|---|---|
| ~33072 | `Throw "member reference is not a structure or union"` | U2 hook |
| ~33081 | `var = find_method_by_callable_arity(...)` / `findMethod` | U1 hook is its `else` |
| ~33265 | `Throw "Unidentified member '<id>' in '<T>'"` | U1 hook (data-member miss) |
| ~34091 | `dlsym fallback: resolve known libc/system functions` | U3 must land BEFORE this |

**Gate: ADOPT the existing owner**, do not invent one —
`Program::madc_dialect_type_spelling` (parser.cpp:2522) is the STD_MADC
predicate pattern. `grep -rn STD_MADC src include` = 24 sites, all
`language_std == STD_MADC`. No UFCS machinery exists today.

Slices: **U1** dot fallback, class receivers · **U2** non-class receivers
(`int`, `char *`, arrays) + the `->` rule · **U3** call syntax, before dlsym ·
**U4** docs + `scripts/ufcs_gate.sh` wired into `fulltest`. Each is its own
commit with trailers and reducers; strict-mode negative control (`--std=c++17`
must still reject) is part of U1.

Two things to carry:

- ⚠️ **`p->f(y)` lowers to `f(p, y)`** — receiver passed exactly as written —
  not `f(*p, y)`. It breaks the C++ identity `p->f()` ≡ `(*p).f()` for the
  *fallback* leg only (member lookup runs first and keeps it), and was chosen so
  C pointer APIs read well: `fp->fclose()` → `fclose(fp)`. The owner's "looks
  good" covered the plan as written, so treat this as ACCEPTED — but it is the
  one decision a reader may want re-opened, and it is a one-line change in U2.
- **U3 is the only slice that changes existing behavior.** Today an undeclared
  `f(x,y)` silently reaches the dlsym fallback with a generic `long` return;
  putting member lookup ahead of it means a program relying on that blind libc
  guess finds a member instead. Owner-specified and defensible, but U3 ships
  with a test pinning the order: declared free → member → dlsym.

Not in scope: operators, constructors, `.` on a namespace, deduction changes.

## 6. Process lessons paid for this session

- **A stale binary reads as a compiler bug.** `headerless-win` reported a real
  1010/1 failure against a PE built eight hours earlier, before the fix under
  test. Fixed the mechanism (`be78c47e`): `packed`, `headerless` and
  `headerless-win` each run their own make target first, and `release-win` got a
  stage. Freshness is the Makefile's job, not the caller's memory.
- **Check the file before "fixing" a stale skill.** `/promote`'s obsolete MIR
  fork step was gone from `.claude/commands/promote.md` (removed in `7fbfa061`);
  what carried the stale text was this session's pre-compaction copy of the
  skill. A restart picks up the file. Nothing needed changing.
- **Count with the right pattern.** `grep -c error` vs `grep -c 'error:'` was a
  5.5× overstatement that would have made #63 look unfinishable.
- **A `continue` with no diagnostic is where a week goes.** The three added this
  release (`materialize fill: DROPPED`, `materialize derived: UNRESOLVED`,
  `forest_restore_decls: SKIPPED`) turned the hunt into minutes.
