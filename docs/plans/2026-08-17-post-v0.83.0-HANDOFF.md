## 4. UFCS — what it is, and its known limits

`--std=madc` only. Full design + every decision: **`docs/plans/2026-08-17-ufcs-madc-dialect.md`**.
User docs: `docs/language/ufcs.md`.

```
x.f(y)   -> viable member f?         use it -> otherwise f(x, y)
f(x, y)  -> viable declared free f?  use it -> otherwise x.f(y)
                                            -> otherwise the usual
                                               unresolved-symbol handling
```

One owner for the entry condition: `Program::ufcs_attempts_here(bool)`. Two
fallbacks: `ufcs_access_fallback` (`.` and `->`, which are the SAME operator in
the fallback leg) and `ufcs_call_fallback`. `ufcs_enabled()` appears **exactly
once** in `src/` and `ufcs_gate.sh` leg 4 keeps it that way.

**Deliberate limits — each is a design step, not a bug to "fix" casually:**

- **Compound first argument** on the call form (`count(get_map(), k)`) does not
  re-form. The receiver is read by bounded lookahead, not by parsing. Widening it
  means parsing the argument before choosing the callee. **Most likely limit to
  annoy a user.**
- **`x.f<T>(y)`** (explicit template args) takes the old error path — lookahead
  sees `<`, not `(`.
- **Dot side viability is BY NAME, on purpose.** Do NOT "improve" it to arity:
  the by-name `findMethod()` behind `find_method_by_callable_arity()` is a
  RECOVERY NET for a documented arity miscount (`count_queued_call_arguments`,
  parser.cpp comment at ~:24874). UFCS ahead of that net breaks working code.
- **Call side is BY ARITY**, because there is no free-function by-type overload
  selector in the tree and the free candidate pool is the whole preference chain.
  Asymmetric on purpose; both halves are justified in the plan's decision 9.
- Static members decline; access control is enforced on the selected overload;
  operators/constructors/namespace-dot are out of scope.

## 6. Process lessons paid for this session

- **MEASURE BEFORE DESIGNING.** Three of the four motivating UFCS calls
  (`size`/`begin`/`empty`) already worked; only `count` was broken. That single
  probe narrowed the design and killed a trigger that would have risked stealing
  calls that resolve today. The probe cost 30 seconds.
- **A lookup with a fallback behind it may be a RECOVERY NET.** Reading why the
  second lookup exists reversed a change I had already proposed out loud.
- **`-Werror=misleading-indentation` caught a real bug**, not a style nit: the
  `Throw` was the body of a brace-less `if`, so inserting a hook before it made
  the throw unconditional — every dot member access would have thrown.
- **Negative-control the negative control.** A `sed -i "s|…||…"` whose `|`
  delimiter collided with `||` in the pattern errored, changed nothing, and the
  gate "passed" — a harness reporting success for a test it never ran.
- **Two of my own justifications were overstated and the controls caught both**:
  the static guard prevents a confusing error, not a silent wrong answer; and the
  `ddARRAY` pseudo-member collision I guarded against does not exist
  (`DataDefARRAY : public DDClass`, so those are already class receivers).
- **Count before quoting a count.** Wrote "eleven reducers"; there are ten.
