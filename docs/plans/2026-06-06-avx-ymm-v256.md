# AVX/YMM `MIR_T_V256` — native >16-byte SIMD (Track 1.6 continuation)

Status: **planned** (design). Owner: open. Repo: the **MIR fork** (`/workspace/mir`),
not madc. Prereq satisfied: ≤16-byte SIMD complete (`MIR_COMMIT 2ffebff`); madc
frontend lowers `DataDefSIMD` → c2mir vector type (madc `e1bf117`/`baf15ad`).

## Why this is *not* a correctness gap

32-byte and 64-byte vectors **already produce correct results today** through
c2mir's scalar-lane lowering (madc tests `testgccwidevectorshortcmp` (32B) and
`testgccwidevectorshift` (64B) pass on the JIT). This track is a **performance +
native-ABI** upgrade: emit packed AVX (YMM) instructions and pass/return 32-byte
vectors in YMM registers per the SysV ABI, instead of scalarizing. So it is
schedulable, not blocking — and the interim (scalarize for JIT, `--emit=c11` →
gcc/clang `-mavx2` for real SIMD performance) remains valid until it lands.

## Scope (survey of the V128 footprint to mirror for V256)

A `MIR_T_V256` sibling touches 7 fork files (V128 mention counts as a proxy):

| File | V128 sites | What V256 needs |
|------|-----------:|-----------------|
| `mir.h` | enum | add `MIR_T_V256`; extend `MIR_vector_type_p` |
| `mir.c` | 28 | type size (32), data item repr + text/binary I/O, reg-class mapping |
| `mir-interp.c` | 111 | packed v256 op execution (or reuse two-v128-halves) |
| `mir-gen.c` | 5 | generic reg-class / spill handling for 256-bit |
| `mir-gen-x86_64.c` | 14 | **YMM register class**, AVX encodings (vpaddd/vaddps/…), spill/restore |
| `mir-x86_64.c` | 8 | **SysV AVX arg/return classification** (SSE+SSEUP → YMM, else memory) |
| `c2mir/c2mir.c` | 321 | select packed v256 opcodes for `vector_size(32)`; keep scalar-lane fallback for unsupported widths/ops |

The two genuinely hard, foundational pieces:

1. **SysV AVX ABI** (`mir-x86_64.c`). A 32-byte vector arg classifies as one SSE
   eightbyte + three SSEUP eightbytes → passed in a single YMM register (or memory
   if no YMM reg is free / `MEMORY` class). Returns analogously in `ymm0`. This is
   the decision that's expensive to get wrong — every later op depends on it.
2. **YMM register class + AVX encodings** (`mir-gen-x86_64.c`). New 256-bit reg
   class, allocation, VEX-prefixed encodings, caller/callee-save discipline, and a
   **runtime AVX-availability gate** (CPUID) — on a non-AVX host the generator must
   fall back to the scalar-lane path rather than emit an illegal instruction.

## Staging (each stage independently testable, mirrors how V128 was built)

- **S0 — type + data I/O (safe foundation).** Add `MIR_T_V256`, 32-byte data
  representation, text/binary round-trip (`mir.c`), `mir-tests` scan/io coverage.
  No codegen/ABI yet. Mirrors V128 commit `55c65ee`. *Inert but upstream-clean.*
- **S1 — interpreter packed ops.** v256 add/sub/mul/bitwise/compare in
  `mir-interp.c` (can compose from two v128 halves initially). Direct-MIR
  `.mir` tests.
- **S2 — x86-64 AVX codegen.** YMM reg class + VEX encodings for the S1 ops,
  CPUID gate with scalar-lane fallback. `-eg` (generated) tests vs `-ei`.
- **S3 — SysV AVX ABI.** v256 param/return in YMM; FFI + interpreter shims;
  validate against gcc/clang-built shared libs (the V128 ABI commits `56e331b`/
  `6de64b4`/`8a16ed6` are the template).
- **S4 — c2mir selection.** Choose packed v256 opcodes for `vector_size(32)`
  arith/cmp/etc.; keep scalar-lane fallback for unsupported ops/widths. Extend
  `c-tests/new/vector-size.c`; add exact GCC 32-byte torture fixtures.
- **S5 — madc bump.** Once the fork track lands on MIR `develop`, bump
  `MIR_COMMIT`; madc needs **no** frontend change (DataDefSIMD already emits the
  `vector_size` attr; c2mir picks the packed path automatically). Re-run the
  32B/64B tests — same results, now native.

64-byte (AVX-512/ZMM) is explicitly **out of scope** here; 64B keeps the
scalar-lane path. (`MIR_T_V512` would be a later sibling if ever justified.)

## Upstream discipline

Design every stage for upstream submission (this is the directive in
`.claude/rules/lowering-vs-raising.md` Tier-3 and KG `Decision{simd_raise_mir_upstream}`).
Keep the scalar-lane fallback intact so `--emit=c11` portability and non-AVX hosts
never regress. No madc-side coupling: the win must arrive purely by bumping the pin.

## Recommendation

Do this as a **dedicated MIR-fork track**, one stage per increment with its own
`mir-tests`/`c-tests` (the way ≤16B SIMD was built), not as a single sprawling
commit. S0 is the safe place to start. The functional behavior is already correct,
so there is no urgency that justifies skipping the ABI design.
