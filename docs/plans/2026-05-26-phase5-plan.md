# Phase 5: Classes & OOP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix 10 class/OOP transpiler test failures: contextual identifiers, ctor/dtor emission, new/delete, inheritance, operator overloading, virtual dispatch, and `prefer calloc` support.

**Architecture:** Grammar alternates let reserved keywords appear as identifiers. The emitter switches from `ClassName__method` to Itanium-mangled names. new/delete emit malloc+ctor / dtor+free. Inheritance emits base casts and destructor chains. Operator overloads and virtual methods emit mangled free functions and vtable structs. `prefer calloc` uses the existing `prefer` keyword grammar.

**Tech Stack:** C++11, Gecko GLR grammar, Itanium ABI mangler (`madc_mangle.h`), c2mir/MIR

### Task 1: Contextual identifiers in Gecko grammar

**Files:**
- Modify: `src/madc_grammar.cpp` (grammar string + token handling)
- Modify: `src/madc_tokenizer.cpp` (token remapping)

The Gecko grammar currently treats `class`, `map`, `set`, `vector`, `list` as
reserved keywords everywhere. They need to be allowed as plain identifiers in
struct members, variable names, enum values, and parameters — just like the
legacy parser's `is_contextual_identifier_token()`.

- [ ] **Step 1: Read the current grammar**

Read `src/madc_grammar.cpp` to understand how the grammar string is structured.
Find where `IDENT` is used in `primary_expression`, `direct_declarator`,
`struct_declarator`, and `enumerator` rules. These are the places where
contextual keywords need to be accepted as identifiers.

Also read `src/madc_tokenizer.cpp` to understand how tokens are mapped from
madc token types to Gecko terminal codes.

- [ ] **Step 2: Add grammar alternates**

In the grammar string in `src/madc_grammar.cpp`, add alternates to the
rules that accept `IDENT` so they also accept `CLASS`, `MAP`, `SET`,
`VECTOR`, `LIST`. The pattern is to add alternates like:

```
contextual_ident : IDENT
    | CLASS | MAP | SET | VECTOR | LIST
    ;
```

Then replace `IDENT` with `contextual_ident` in:
- `direct_declarator` (for variable/parameter names)
- `struct_declarator` (for struct member names)
- `enumerator` (for enum value names)
- `primary_expression` (for using these as variable references)

Be careful NOT to change type-specifier positions where CLASS/MAP/etc.
should remain keywords (class definitions, container declarations).

- [ ] **Step 3: Build and test**

Run: `make -C src`
Then test each of the 5 failing tests:
- `bin/madc --backend=mir tests/testaddrclass.mad`
- `bin/madc --backend=mir tests/testclassident.mad`
- `bin/madc --backend=mir tests/testclassidentifier.mad`
- `bin/madc --backend=mir tests/testenumclass.mad`
- `bin/madc --backend=mir tests/testmapidentifier.mad`

Run: `make -C src fulltest` to verify no regressions.

- [ ] **Step 4: Commit**

```bash
git add src/madc_grammar.cpp src/madc_tokenizer.cpp
git commit -m "feat: allow class/map/set/vector/list as contextual identifiers in Gecko grammar"
```

- [ ] **Step 1: Add operator name mapping**

In `src/madc_mangle.cpp`, add a function that maps C++ operator symbols
to their Itanium ABI operator codes:

```cpp
static std::string operator_code(const std::string &op)
{
	if (op == "==") return "eq";
	if (op == "!=") return "ne";
	if (op == "<")  return "lt";
	if (op == ">")  return "gt";
	if (op == "<=") return "le";
	if (op == ">=") return "ge";
	if (op == "+")  return "pl";
	if (op == "-")  return "mi";
	if (op == "*")  return "ml";
	if (op == "/")  return "dv";
	if (op == "%")  return "rm";
	if (op == "=")  return "aS";
	if (op == "+=") return "pL";
	if (op == "-=") return "mI";
	if (op == "*=") return "mL";
	if (op == "/=") return "dV";
	if (op == "<<") return "ls";
	if (op == ">>") return "rs";
	if (op == "[]") return "ix";
	if (op == "()") return "cl";
	if (op == "++") return "pp";
	if (op == "--") return "mm";
	if (op == "!")  return "nt";
	if (op == "~")  return "co";
	if (op == "&")  return "an";
	if (op == "|")  return "or";
	if (op == "^")  return "eo";
	return "";
}
```

- [ ] **Step 2: Add the mangling function**

In `src/madc_mangle.cpp`:

```cpp
std::string itanium_mangle_operator(const std::string &class_name,
                                     const std::string &op,
                                     const std::vector<std::string> &param_types)
{
	std::string code = operator_code(op);
	if (code.empty()) return "";
	return "_ZN" + source_name(class_name) + code
	       + "E" + itanium_encode_params(param_types);
}
```

Add the declaration to `include/madc_mangle.h`:

```cpp
// Mangle an operator: ("Counter", "==", {"int"}) → "_ZN7CountereqEi"
std::string itanium_mangle_operator(const std::string &class_name,
                                     const std::string &op,
                                     const std::vector<std::string> &param_types);
```

### Task 4: Fix dtor+return bracing

**Files:**
- Modify: `src/madc_emit_c.cpp` (return statement emission in presence of scope destructors)

- [ ] **Step 1: Find the return emission path**

Search `src/madc_emit_c.cpp` for `AN_RETURN_VAL` or `return` emission.
Find where destructor calls are injected before `return`. The bug is that
when a return is inside a conditional without braces, the dtor call and
return are emitted as two separate statements — only the dtor is inside
the `if`.

- [ ] **Step 2: Fix bracing**

When emitting destructor calls before a return statement, always wrap
both the dtor calls and the return in a brace block:

```cpp
// Before return with pending dtors:
emit_indent();
O("{\n");
indent_level++;
// emit dtor calls
emit_indent();
O("return expr;\n");
indent_level--;
emit_indent();
O("}\n");
```

### Task 7: Virtual dispatch — vtable struct + vptr + indirect calls

**Files:**
- Modify: `src/madc_emit_c.cpp` (struct emission, ctor emission, call site emission)
- Modify: `src/madc_sema.cpp` or `src/madc_sema.h` (track virtual methods)

This is the most complex task. It requires:
1. Detecting which methods are virtual (from the AST `virtual` keyword)
2. Emitting a vtable struct type per class
3. Adding `__vptr` field to the class struct
4. Emitting a static vtable instance per concrete class
5. Initializing `__vptr` in constructors
6. Rewriting virtual call sites to use indirect dispatch

- [ ] **Step 1: Track virtual methods in sema**

Extend `SemaClassInfo` in `src/madc_sema.h` to include:

```cpp
std::vector<std::string> virtual_methods;  // ordered list of virtual method names
std::map<std::string, std::string> virtual_method_sigs;  // name → return type
```

In `src/madc_sema.cpp`, when walking class methods, detect the `virtual`
keyword and populate these fields.

- [ ] **Step 2: Emit vtable struct**

In `emit_class_def`, if the class has virtual methods, emit a vtable type
before the class struct:

```c
struct Shape_vtable {
    double (*area)(struct Shape *);
    void (*describe)(struct Shape *);
};
```

Then add `struct Shape_vtable *__vptr;` as the first field in `struct Shape`.

- [ ] **Step 3: Emit vtable instances**

After all class definitions, for each concrete class (including derived),
emit a static vtable instance:

```c
static struct Shape_vtable Circle_vtable_instance = {
    (double (*)(struct Shape *))Circle__area,
    (void (*)(struct Shape *))Circle__describe,
};
```

Derived classes override slots with their own implementations, falling back
to base implementations for un-overridden virtuals.

- [ ] **Step 4: Initialize vptr in constructors**

In constructor emission, add `__this->__vptr = &ClassName_vtable_instance;`
as the first statement.

- [ ] **Step 5: Rewrite virtual call sites**

When emitting `obj.method(args)` and the method is virtual, emit:

```c
obj.__vptr->method(&obj, args)
```

instead of the direct `ClassName__method(&obj, args)` call.
