# Release v0.106.0 — 2026-10-22

**Table-driven unwinding, self-describing modules, and C++ conformance.** madc's
exceptions now unwind through the host platform's own unwinder: MIR describes
every generated frame as DWARF CFI and emits unwind records in ELF, PE/COFF and
Mach-O images, so a throw runs the live objects' destructors across every frame
it crosses on all five MIR targets — through `RtlUnwindEx` on Windows and the
Apple arm64 unwinder on darwin. Capabilities that were wired into the core —
markdown, git and the web UI target — become self-describing madc modules
imported by name, the release pack gains a C layer that `.c` compiles bind, and
C++ conformance moves forward on throws, vtables, exceptions and templates.
madc's command line moves to one option reader with gcc parity, and the dialect
gains faces for paths, project manifests and the user-configuration directory.

## Highlights

- **Exceptions unwind through the host's own unwinder (B205).** MIR describes
  every generated frame as DWARF CFI and emits unwind records in ELF, PE/COFF
  and Mach-O images, opening an unwind region per automatic cleanup variable, so
  a throw destroys the live objects of every frame it crosses — on x86-64,
  aarch64, ppc64, riscv64 and s390x (MIR builds for ppc64, riscv64 and s390x
  again), through `RtlUnwindEx` on win64 and the Apple arm64 unwinder on darwin.
  An object another toolchain links names madc's runtime as a g++ object names
  libstdc++: add `-L<dir>/lib -lmadc_rt` to that link.
- **A class-type exception is owned by its throw and matched by type (B202),
  and a throw operand is implicitly moved.** A class object thrown from inside a
  `try` is moved into the exception object as [class.copy.elision]/3 prescribes,
  and each handler matches the thrown object by type.
- **Virtual functions take one vtable slot per signature.** Overloads of one
  virtual name each take their own slot, in declaration order, as the Itanium
  C++ ABI lays them out, so overriding one overload no longer redirects every
  overload of that name.
- **A return reads its value before the scope's cleanups run.** A return in an
  `__attribute__((cleanup))` scope reads its value into the return register or
  the result object before the cleanups run, so a cleanup that frees or
  overwrites the object does not change what the function returns.
- **Capabilities become self-describing modules imported by name.** markdown,
  git and the web UI target are no longer wired into the core; `import
  markdown;`, `import git;` and `import ui_web;` open self-describing modules
  found on the module path (`--module-path`) in place of the madcmark fragment,
  the `-lmadcgit` link and the built-in web target. `--import=NAME` imports a
  module ahead of the program (with no source it only tries the import — exit 0,
  or the import error and exit 69), and madc.ini's `modules = NAME` now imports
  the module instead of linking `-l`.
- **The release pack gains a C layer that C programs bind.** The pack freezes
  the standard C headers a second time, under C, so a `.c` compile binds them;
  system headers bind correctly across nested re-entry, bound using-declaration
  imports, auto-include parse order and re-inclusion.
- **madc's command line is read by one option reader with gcc parity.** An
  unrecognized option is an error with a "did you mean" suggestion, a missing
  value is an error, `--` ends madc's options, `@file` response files expand,
  `-std=` is accepted, and `--help=json` and shell completion scripts are
  generated from the one option table.
- **The dialect gains faces for paths, project manifests and the
  user-configuration directory.** A host calls madc's own path, manifest and
  config-directory readers and writers rather than carrying a copy, with a
  Windows `%APPDATA%` arm and `madc::path_generic`.
- **Member templates and type traits resolve per instantiation.** A member
  template's placement new constructs at a typed address, a constructor
  template's mem-initializer and forwarding-reference instances answer per
  argument, and `__is_same` and the class-property traits answer type identity
  through the kind accessors.
- **Darwin parity.** Mach-O objects and executables carry unwind tables, the
  prelude honours NDEBUG, the generated predefined-macro table covers the darwin
  capture gaps, `-static-libmadc` covers the libSystem directory, and a
  namespace-scope class keeps its source name in its C++ spelling.
