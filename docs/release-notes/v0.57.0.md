# Release v0.57.0 — 2026-07-28

The libc++ burn-down session: eight core-C++ defects fixed in one chain, and
the `-stdlib=libc++` parse frontier fell from `<cwchar>` to the single last
blocker in front of `<string_view>` and `<string>`. Every defect was a gap in
madc's own generic machinery — none libc++-specific — and every fix ships an
oracle-verified test matching g++ and clang++ byte-for-byte. Suites: 784 JIT /
768 EXE / 768 OBJ, zero failures, warning ratchet at zero.

- Qualified lookup now sees a namespace's INLINE namespace set while the
  block is still open ([namespace.qual]) — `find_namespace_member()` owns
  the walk, nine flat-probe consumers adopted. This was `<cwchar>:202`,
  the gate in front of the whole libc++ string stack.
- Namespace-NAME resolution walks the inline set too:
  `using std::__math::fpclassify;` canonicalizes to `std::__1::__math`
  (`canonical_nested_namespace` + path fold, four resolvers adopted).
- `using X = void (*)();` — using-alias accepts the abstract
  function-pointer declarator (same `parseFnPtrParams` owner as typedef).
- Self-referential class instantiation is bounded in BOTH lanes and BOTH
  cache regimes — libc++'s `allocator : __non_trivial_if<..., allocator<_Tp>>`
  made `#include <string>` a stack-overflow SIGSEGV; one in-flight registry
  now serves the incomplete shell on every re-entry shape.
- Braced construction: `Class::NestedTag{}` temporaries parse, and a braced
  list on a class with constructors ranks the ctor overload set
  ([dcl.init.list]/3) — the aggregate reroute had silently dropped every
  argument after the first for ANY `T v{a, b}`.
- `__underlying_type(T)` implemented (the intrinsic both standard libraries
  build `std::underlying_type` on): enums record their declared fixed base
  or the canon range rule; partial specs of a declaration-only primary
  reach the spec match.
- New libcxx_gate legs: `<cwchar>` compiles and runs; the CRTP base-arg
  shape is bounded on the forced-legacy lane; `<string>` terminates loudly,
  never with a signal.
- Frontier: both `<string_view>` and `<string>` now stop at ONE recorded
  defect — `Gap{common_type_dependent_member_key_explosion}`, the
  dependent-member-type tsubst family (unresolved `common_type<...>::type`
  args compound the instantiation key; the MADC_MEM_LIMIT guard trips
  loudly and names the knob).
