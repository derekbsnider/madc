# Release v0.7.0 — 2026-04-16

Completes SMAUG Phase D variadic function support. madc can now compile C functions that use `va_list`/`va_start`/`va_arg`/`va_end`, enabling SMAUG's `ch_printf`, `log_string`, and other formatted output wrappers. Also fixes a long-standing for-loop parser bug that prevented `i++`/`i--` in the increment position.

## Highlights

- **`va_list` / `<stdarg.h>`** — Full variadic function support: `...` in declarations, `va_start`/`va_end` macros, `va_arg` as a compiler intrinsic. Packed `int64_t[]` buffer design avoids the System V `va_list` struct (impossible in asmjit Compiler mode).
- **`vsprintf`/`vsnprintf`/`vfprintf` helpers** — Built-in `__madc_vsprintf` and friends handle format-string-aware variadic output. Redirected via `#define` in embedded `<stdarg.h>`.
- **`-rdynamic` linker flag** — Exports binary symbols so JIT code can call built-in helpers via `dlsym(RTLD_DEFAULT)`.
- **39 embedded headers** — `<stdarg.h>` added (was 38). All standard headers used by SMAUG 1.8 are now embedded.
- **For-loop increment bug fixed** — `for (i = 0; i < N; i++)` now works. All increment forms (`i++`, `i--`, `++i`, `--i`, expression) parse correctly. Root cause was the conditional peek-stop in `parseExpression` leaving the `;` separator unconsumed.
