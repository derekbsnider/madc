# Release v0.94.0 — 2026-08-20

Upstream-community MIR hardening: three codegen correctness fixes landed
in the in-tree fork, each attributed to its original contributor, plus
one upstream-reported crash verified not to affect us.

- **Wrong code at `-O2`/`-O3` fixed**: ssa_combine's address folding
  walked through loop-header PHIs whose registers are rewritten along
  the backedge — the `cycle_phi_p` guard only caught single-BB
  self-loops. Now keyed on the CFG's own back-edge marks. Reported with
  reducers by ThePeiLin (vnmakarov/mir#467); reproduced here verbatim,
  green at every level after the fix. Our fix, queued for upstream.
- **Register-allocator spill-rewrite table bounded at run time**
  (adopted from upstream PR #468 by Bill Hlavacek) — the assert-only
  bound vanished under NDEBUG and `MIR_USE` has no fixed operand count.
- **aarch64 displacement gate agrees with the encoder** (adopted from
  upstream PR #466 by Richard Davison) — byte size, not log2; fixes a
  fatal generation failure on legal displacements and un-blocks
  addressing-mode folds on our darwin arm64 lane; the contributor's
  gate-vs-encoder test rides along.
- **Upstream issue #429** (ARM64 by-value struct >16B, pointer to
  static array): both reducers pass on real Apple Silicon against our
  fork — the darwin ABI arc already covers those patterns.

Validation: c2mir-gen-test and c2mir-gen-test3 at the exact 1143/2286/0
baseline, all reducers green, fulltest and EXE lane at baseline.
