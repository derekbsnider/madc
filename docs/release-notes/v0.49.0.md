# Release v0.49.0 — 2026-07-26

Forest carriers **S4: the shared shape**. The frozen forest can now ride
the **libmadc image**, so a packaged install — a thin CLI plus the
versioned `libmadc.so` — serves the compiler *and* every embedding host
from one container. The public embedding API gains the frozen-forest
knob family (bind / failure policy / sandbox gate), and the
`enable_external_forest=false` negative path that S3 explicitly left
untested is now covered end-to-end by a real host program.

- **Discovery arm 2 — the library image.** `madc_self_lib_path()`
  (`dladdr` on a libmadc-resident symbol) resolves the image that holds
  madc's code and probes it with the same per-format reader; in the
  monolithic shape that path *is* the executable arm 1 already covered,
  so the arm is skipped. The sidecar arm gains `<lib>.forest` after
  `<exe>.forest`.
- **Image arms are never sandbox-gated.** `enable_external_forest`
  gates only what comes from *outside* the images (`<exe>.forest`,
  `<lib>.forest`, `$MADC_FOREST`). A strict, sandboxed host still binds
  the groves its own library carries — that asymmetry is the point of
  the shared shape.
- **`--enable-shared` (thin CLI).** New configure axis: the CLI links
  the shared libmadc instead of embedding it (monolithic remains the
  default). In that shape `make release` packs `lib/libmadc.so` and
  `make install` ships the packed library — an installed CLI of 133 KB
  next to an 11.5 MB library that carries all 240 frozen units.
- **Public embedding API.** `madc::compile_options` gains
  `enable_forest_bind` (on by default — a host linked against a packed
  libmadc gets grove-backed system headers for free), `forest_missing`
  (`silent_fallback` / `loud_fallback` / `strict_require`) and
  `enable_external_forest`; `madc::security_policy` gains
  `allow_external_forest`, clamped off under `system_locked` authority.
- **One owner for "may this compile bind frozen state".**
  `Program::forest_bind_enabled` folded into `RegistrationPolicy`, so it
  flows engine → program → child → host like every other knob; a
  runtime-eval child now inherits the forest knobs instead of reverting
  to the liberal defaults.
- **`scripts/forest_library_gate.sh`** (permanent, in `fulltest`) — nine
  legs over a staged `bin/` + `lib/` install: thin-CLI parity,
  library-image bind with output parity, arm ordering, `<lib>.forest`,
  and the host legs with no CLI knob (strict + sandboxed binding through
  the library, the external-forest refusal, strict-on-empty, silent
  library default). `tests/libmadc_forest_smoke.cpp` is the public-API
  host it drives.
- **Build fix:** a bare `make -C src` had been building nothing but the
  forest-shape stamp since v0.48.0 (a rule above `all:` became the
  default goal). `.DEFAULT_GOAL := all` is now explicit.
- **Validation:** fulltest **756/0/0/9**, `--exe` **740/0**, thin-CLI
  parity suite **756/0/0/9**, and the product `--enable-shared` shape
  (release packs the library) arbiter **756/0/0/9** with an
  installed-tree run binding 240 units through the library image.
- **Stated boundary:** the darwin **dylib** packaging shape
  (`-dynamiclib` + `@rpath`, its `-sectcreate` carrier, Mac hardware
  legs) is not in this slice; the discovery code is platform-neutral, so
  what remains there is packaging plus hardware validation.

The MIR fork is unchanged: this release ships against
`1.0-madc.0.47.0`.
