# Release v0.8.0 — 2026-04-17

Completes SMAUG Phase E (C arrays, brace initializers, struct interop, `select()`) and lands the Phase F foundation needed to begin porting the SMAUG 1.8 source tree. The first `.c → .mad` file (`MadSMAUG/src/hashstr.mad`) is underway, and every language gap surfaced during the port has been fixed in madc proper. 74 integration + 25 unit tests pass.

## Highlights

- **C fixed-size arrays** — 1D and multi-dim (`int a[N]`, `int m[N][M]`, `int cube[N][M][K]`), plus global/static forms (`struct X *arr[N]` at file scope, heap-allocated).
- **Brace initializer lists** — `int a[] = {1,2,3}` with explicit/inferred size and partial zero-fill; struct initializers `struct Foo v = { ... }` with scalars, pointers, `char*` (auto-coerced from `std::string` literal), and `std::string` members; array-of-structs `struct Entry tab[] = {{"a",1},{"b",2}}`.
- **String-literal char-array init** — `char msg[] = "hello"`, `char buf[N] = "hi"`, and `char *p = "literal"` sugar all produce the same backing storage.
- **Chained member access** — `a->b->c`, `a->b.c`, `a.b.c`, and `tab[i].name` all compile through a unified dot/arrow chain.
- **`str.length()` / `str.size()`** — `std::string` instance methods; the mis-firing pre-registered `strlen` builtin was removed so `strlen(char *)` now resolves to libc via dlsym.
- **Struct interop for libc types** — `struct tm` (56 B), `struct timeval` (16 B), `struct fd_set` (128 B) with glibc-x86-64-matching layouts. `FD_ZERO`/`FD_SET`/`FD_CLR`/`FD_ISSET` macros forward to `__madc_fd_*` helpers; `select()` works end-to-end against real pipes. Fixed a latent `safemov(Gp, Mem)` bug that silently read 8 bytes for sub-qword struct members.
- **Raw-pointer subscript `ptr[i]`** — for `int *`, `char *`, etc., with SIB scaling by the pointed-to type's size. Unblocks idiomatic C interop like `pipe(pfd); int rfd = pfd[0]; FD_SET(rfd, &rfds);`.
- **Self-referencing structs, three-word compound types, `void` as sole parameter** — `struct X { struct X *next; };`, `unsigned short int`, `long long int`, `int f(void)`; pre-registering the struct tag before body parse unblocks the self-ref pattern.
- **Multi-variable declarations, global fixed arrays, `stdin`/`stdout`/`stderr`** — `int a, b, c;`, `char *p, *q;`; `struct X *t[SIZE];` at file scope; `stdin`/`stdout`/`stderr` lazy-registered from libc's dlsym values for `fprintf` et al.
- **For-loop comma expressions, forward decl → definition, `__FILE__`/`__LINE__`** — `for (a=0, b=1; cond; i++, j--)`; forward function declaration followed by a matching definition no longer double-pushes parameters; `__FILE__`/`__LINE__` expand per call-site inside `#define` bodies.

## Additional Fixes & Ergonomics

- **Crash handler with backtrace** — catches `SIGSEGV`/`SIGABRT`/`SIGFPE`/`SIGBUS`/`SIGILL`, prints signal + fault address + `backtrace_symbols_fd` to stderr, then re-raises so the shell sees the real exit status.
- **`cc.newXxx(name)` format-safety sweep** — 32 direct call sites in `compiler.cpp` routed through `"%s"` format, preventing crashes on variable names that contain `%` (our generated literal names like `__literal__tab[%ld]`).
- **`emit_struct_init` aliasing fix** — the `std::string`→`const char *` coercion was mutating a cached `Operand` in `operand_map` via reference; now uses a local `Operand` so global literal variables survive repeated struct-init use.
- **`register` before struct / typedef** — previously limited to primitive types; now delegates through the same keyword path as `static`.
- **Unary minus after a keyword** — `return -1;`, `if (-x > 0)` no longer misfire as "Missing operand"; `isUnaryPosition`/`isPostfixPosition` now treat keywords as unary-opening contexts.
- **Multi-file bootstrap convention** documented — app-named top-level file (e.g. `smaug.mad`) `#include`s sources in dependency order with `main()` last.
