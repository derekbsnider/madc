# Release v0.40.0 — 2026-07-24

The ctor/init-array release (ELF-completion slice 3). Native images adopt
the platform initializer model: per-TU constructors ride a real
`.init_array` section instead of a wrapped `main`, so translation units
with C++-style dynamic initializers now link and run together in every
native lane — the last structural fence on multi-object linking of ctor
TUs is lifted. Ships against MIR fork release `1.0-madc.0.40.0`.

## Highlights

- **Per-TU init arrays (gcc-shaped)** — each TU with dynamic global
  initializers (or `<ns_madc>`) gets a static, TU-unique init function
  registered in the image's `.init_array`; the `__madc_global_init`
  main-wrap is retired in the native lanes (the JIT keeps it). Two ctor
  TUs no longer collide at the merge, and a ctor TU that isn't main's TU
  no longer loses its ctors.
- **`DT_INIT_ARRAY` everywhere, `DT_INIT` retired** — executables and
  PIEs carry the array inside the RELRO lead region (relocated,
  protected, then read); shared objects' inits run at `dlopen`; the
  in-process loader exposes the merged array and the run lanes walk it
  before `main`. glibc ≥ 2.34 documented floor for executables.
- **External-linker parity** — the `.o`'s section is a real
  `SHT_INIT_ARRAY`, so a gcc/ld link of madc `.o` caches collects it
  natively and runs every TU's inits (gate-proven).
- **`sys.*` hardening** — population moves into the TU init via a new
  guarded `__madc_sys_init_once`: a madc-built module dlopen'd
  mid-program no longer stomps the running script's `sys.path`/`sys.argv`
  mutations.
- **Stale-cache safety** — a pre-init-array ctor cache (defines
  `__madc_global_init`) is refused at merge with a re-emit message
  instead of silently skipping its ctors.
- **Fork fix: c2mir `-g` debug-capture reset** — the R5 DWARF capture's
  process-static records made a second `-g` compile in one process a
  latent use-after-free; `c2mir_finish` now resets the state.
- **Suite state** — fulltest + packed arbiter 753/0/0/9; `--exe` and
  `--obj` lanes 737/0 each; fork object + load-object lanes 1139/2278 ×2;
  ten container gates including a gdb source-level breakpoint inside a
  per-TU init on the merged `-g` PIE.
