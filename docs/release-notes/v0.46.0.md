# Release v0.46.0 — 2026-07-25

The frozen forest reaches macOS. Hosted darwin madc binaries now ship
PACKED (forest-carriers plan S1): the darwin standard-header groves are
cross-frozen in the build container and embedded as a `__MADC,__forest`
Mach-O section, and standard `#include`s BIND from the forest instead of
re-parsing the embedded prelude text — verified green on Apple hardware
on both architectures, with grove-bind output byte-identical to live
parse. The gate run also caught and fixed a real target-independent
parser bug in typedef-of-class registration.

- **Mach-O forest carrier:** appended blobs are AMFI-illegal on signed
  Mach-O (the file must end exactly at the code signature), so the
  darwin self-image carrier is a `__MADC,__forest` section placed at
  link time via `-Wl,-sectcreate` — lld signs AFTER section layout, so
  the build path needs **no re-signer**. The ELF trailer carrier on
  Linux is untouched.
- **Cross-freeze:** the freezer is the same-arch Linux-hosted cross
  madc, which now embeds the identical per-target darwin prelude the
  hosted binary carries (`DARWIN_PRELUDE_TARGET` covers cross + hosted
  MODEs) — same source tree, same embedded text, same target facts ⇒
  same context hash and config word across the cross-freeze.
- **Read-back:** `cir_forest_map_image`'s darwin arm probes the running
  image's section via `getsectiondata` (zero-copy, slid,
  process-lifetime) before the file probe; `--dump-forest` on a Mac
  reads 30 units from the binary's own section.
- **Pack tooling:** `scripts/forest_pack_darwin.sh` generates the freeze
  TU from the prelude's `.MANIFEST` (one owner of the header list) and
  fails loud unless every header name is a directory unit; hosted MODEs
  regained zstd via per-target static builds so the consumer reads the
  release codec.
- **fix(parser): typedef-of-class registers the full typedef surface.**
  Apple's `typedef struct __sFILE {... fnptr members ...} FILE;` routes
  through the class parser, whose typedef branches registered only the
  type maps — the forest freeze never saw the alias, and grove-bound
  consumers lost `FILE` while live parse resolved it. Both branches now
  record `user_typedef_names` + a file-scope dkTypedef TopDecl (the
  using-alias precedent). Pinned by the new Linux `forest_bind_gate`
  case `[fnptrbody]`.
- Gates: Linux fulltest 756/0/0/9 with all forest gates green; packed
  arbiter 240 units, bind cache == no-cache, 756/0/0/9 through
  `bin/madc-release`; native-exe lane green; Mac hardware matrix green
  on A64 native + X64 under Rosetta (JIT/AOT × `.mad`/`.c`).

MIR fork unchanged since v0.45.0 — madc v0.46.0 ships against fork
release `1.0-madc.0.45.0` (no new fork tag).
