# Release v0.64.1 — 2026-07-31

Patch release: two bugfixes off the libc++ input-stream chain, one of
them a flavor-independent wrong-codegen defect present in v0.64.0 —
an unnamed virtual base whose class declares a non-default constructor
first was constructed through the wrong overload.

- **Virtual-base default-construction selects its ctor by overload
  resolution** — the vbase arm called whichever overload owned the
  unsuffixed `ClassName__ClassName` symbol with no arguments
  ([class.base.init]p9). Header-free reducer fails on the v0.64.0
  binary; under libc++ this broke every `istringstream`
  default-construction. Now routed through `select_ctor_overload` +
  `ctor_call_assemble`, the one ctor-call assembler. Gate
  `testvbasedefault`.
- **Completeness-on-demand for pending forward instantiations** —
  libc++'s `<iosfwd>` stream typedefs left `istringstream` an empty
  shell: declarations mis-parsed as function declarations and
  `sizeof(istringstream)` silently measured 0. New
  `complete_class_type_on_demand` helper adopted at by-value class
  declarations and `sizeof`/`alignof` operands. Gate
  `teststreamdecl_libcxx`.
- Suite 885 → 887; MIR fork unchanged (`1.0-madc.0.63.0`).
