# madc v0.105.0

**The live REPL and the pack slices.** Everything since v0.104.0: a `madc -i`
session now behaves like a buffer you keep editing — a function, a variable or a
type you define again takes effect at once, an edit to the REPL buffer reparses
live, and Restart and Run All replays the whole buffer in a fresh session. On the
pack side, the forest pack now holds every system header the platform ships and is
cut into per-unit slices, so a packed madc compiles any system-header program on a
machine with no headers on disk and a bind loads only the units a program
includes. madcide releases alongside as **madcide 0.8.0**, pinned to madc 0.105.0,
carrying the live reparse and Restart and Run All to its REPL pane.

## Features

- **Redefine a function in a live session.** A function whose body an earlier
  entry already linked can be defined again, and every call then reaches the
  newest body — a later call, a caller compiled before the redefinition, a
  function pointer taken before it, and an inline or in-class member function
  (Julia's rule). Before, C refused the second body and C++ / madc silently kept
  the first.

      madc -i
      int f() { return 1; }
      int f() { return 2; }   // the next f() returns 2, everywhere

- **Redefine a variable in place.** An object defined again with the same type is
  initialized again in the same storage, so every function and every pointer taken
  earlier reads the new value; an object with a destructor — the madc `var`
  carrier included — is destroyed first and constructed again in place. A type
  change, a `const` object and an array whose size changes are refused with a hint
  to `%run`, and keep their value.

      int n = 1;
      int n = 42;             // every earlier &n reads 42

- **Redefine a type — the name's next version.** A struct, union or class defined
  again with the same data members is the same type (C23's identical-redefinition
  rule), and a class's member functions are redefined. Defined with other members
  it becomes the name's next version: the name means the new type, while the
  objects, functions and pointers made with the earlier one keep it, shown as
  `P#1` (Julia 1.12's world age). Mixing versions is a type error, and a C++
  function redefined for the new version is an overload mangled as g++'s `abi_tag`
  would (`getx(P[abi:v2])`).

      struct P { int x; };
      struct P { int x; double y; };   // P now means the new type; old objects keep P#1

- **The REPL buffer reparses live.** An edit a colon command makes to the REPL
  buffer takes effect at once: the entries it changed are read again as
  definitions only, so functions are redefined and variables re-initialized while
  statements never run again. An edit that gives a type a new version also re-reads
  the functions below it that name the type. Two dialect verbs,
  `madc::session_edited` and `madc::session_rebuild`, give a host the live reparse
  and the rebuild.

      :%s/return 1/return 2/    # the next call to the edited function returns 2

- **Restart and Run All.** `%run` with the REPL buffer current — and madcide's
  Build ▸ Restart and Run All (`%runall`) — restarts the session, replays the
  whole buffer entry by entry, then runs the buffer's `main` when it defines one
  that no entry called (argv[0] is `[REPL]`).

      %run                      # a fresh session, the buffer replayed, its main run

- **Objects with static storage duration are destroyed at exit.** A global, an
  array global or a block-scope static now has its destructor run at exit, in
  reverse order of construction and interleaved with the `atexit` handlers
  registered between constructions, in the JIT and in native executables. A
  madc-built shared object unloaded before exit runs its destructors at the unload,
  and `atexit`, `at_quick_exit` and `pthread_atfork` link from madc's own startup
  members.

      static Logger log;        // its destructor runs when the program exits

- **A packed madc compiles any system-header program with no headers on disk.**
  The forest pack now holds the exact text of every header the platform's C
  library, kernel and C++ standard library install — not only the handful earlier
  packs listed — and the release (packed) madc reads those core system headers from
  libmadc rather than opening, stat-ing or probing /usr/include. A name libmadc
  does not carry (an add-on library's header) is still searched on disk as gcc
  searches it, and `--no-embedded-headers` is the one switch that sends the core
  headers back to disk.

      madc prog.c               # #include <any system header> compiles with nothing in /usr/include

- **The forest pack is cut into per-unit slices; a bind loads only what a program
  includes.** The pack carries a frozen index — a per-unit seed list, an inverted
  name index, and a recordability bitmap — so a bind visits and judges only the
  slices of the units a program's include closure reaches, builds a derived type on
  first use, and reads a node unit's records block by block. A product is restored
  only in the units whose parse requires it, so a `<vector>` bind no longer carries
  the `basic_string<char16_t>` products `<string>`'s parse made.

      // <vector>'s packed front-end cost drops from 352M to 76M instructions

- **A packed compile that binds nothing never decodes the pack.** A compile opens
  the bind container to its directory only and decodes the string pool and type
  arena only when an include actually binds a packed unit. A dialect compile binds
  no packed unit, so it no longer decodes the whole container on every fragment
  include, and the dialect prelude now binds directly from its own frozen unit
  under `--std=madc` instead of being parsed from text on every compile.

      madc hello.mad            # a bare println("hi") drops from 86.9M to 15.1M instructions

## Fixes, internals and infrastructure

- **Conversion correctness.** A class's `template <typename U> operator Val<U>()`
  converts to the class deduced from the target ([temp.deduct.conv]); passing a
  class by value where an unrelated class is expected, with no conversion between
  them, is now a compile error (`no matching constructor for call to 'B(A)'`)
  instead of a silent wrong answer; a global declared `extern` ahead of its
  definition is initialized by the definition; and `__has_trivial_destructor(var)`
  is false, matching g++ and clang++ with `std::string`.

- **Session and exit robustness.** A refused `MIR_link` no longer survives into
  `MIR_finish` and crashes at a session's end; on Windows `quick_exit` runs only
  the `at_quick_exit` handlers, not the `atexit` ones; and a frozen `--run-frozen`
  binary's trap prebinder leaves madc's startup members alone, so the Windows
  release pack's frozen module links.

- **Pack and dialect correctness.** A standard type the pack only names stays
  incomplete until a bind requires it whole; a namespace's unscoped enumerator
  keeps its namespace through the pack; a header first included by a later REPL
  entry parses its text; and a packed dialect program that imports a module
  (`ns_markdown`, `ns_git`, `ns_ui_web`) compiles, its import directive replayed
  from a frozen preprocessor event.

- **Build tooling.** `scripts/gen_embedded_headers.sh` refuses a run that reads no
  header, so a build root with no `/proc` can no longer link a madc carrying no
  embedded headers; and three per-token costs leave the `--std=madc` parse path
  (the session type-identity lookup, operator-id recognition, and abi-tag
  mangling).
