# Release v0.29.0 — 2026-06-11

The backend-correctness release. MIR-gen `-O2` now reaches **exact `-O1`
gcc.c-torture parity** — 1567 passed at both levels with byte-identical
failsets — closing the "O2 is broken" item open since the 2026-06-02
experiment. All 8 O2-only failures were root-caused to five real c2mir/MIR
bugs (each reproduced on stock `c2m` first) and fixed at the deepest layer in
the madc MIR fork, which is also now synced with everything useful from
upstream `vnmakarov/mir`. The fork is pinned at `9ab36fb`.

## Highlights

- **O2 = O1 torture parity (1567/1652, byte-identical failsets).** madc's
  `-O2`/`-O3` flags are no longer behind a known-broken generator; the old
  "GVN mem-forwarding" theory is retired — no optimization-disabling shim
  was needed.
- **GVN treated struct `va_arg` as CSE-able:** `MIR_VA_BLOCK_ARG` joined
  `fixed_place_insn_p`; two struct fetches no longer collapse into one
  (fixed `strct-varg-1`, `920908-1` SIGSEGVs).
- **The classic lost-copy problem in out-of-SSA:** a self-loop block's
  back-edge phi copy lands before the tail branch, so a loop condition
  testing the phi var read the *next* iteration's value — `while (i-- > 0)`
  ran one iteration short (fixed `stdarg-3`, `pr43236`).
- **Union type-punning aliasing hole:** MIR core gains an alias-conflict
  relation (`MIR_add_alias_conflict` / `MIR_alias_conflict_p`); c2mir
  registers union-class ↔ member-leaf-class conflicts (fixed `pr41463`,
  `pr41395-2`).
- **`__attribute__((optimize("-fno-strict-aliasing")))` honored**
  per-function through c2mir AND the madc front end (lexer allowlist,
  mid-declaration attribute parsing, CIR `N_ATTR` forwarding,
  `FuncDef::no_strict_aliasing`) — TBAA suppressed for the attributed
  function, surviving MIR inlining (fixed `alias-1`, `pr79043`).
- **Interpreter FFI varargs fix:** `_MIR_get_ff_call` over-counted XMM slots
  for mixed-class block args, landing each `{double,long}`-style vararg
  struct's SSE half one register too high (fixed `stdarg-3` under `-ei`).
- **Upstream adoptions:** PR #430 (computed-goto RA: `laddr` OUT_FLAG +
  `jmpi` simplified-RA), PR #432 (GVN narrow-reload sign/zero extension —
  independently root-caused to the same site before the PR was found),
  PR #433 (jump_opt keeps `laddr`/lref-referenced labels alive), PR #434
  (aarch64 long-double stack rounding, for the ARM64 track). PRs #418/#420
  were already carried. Triage record:
  `docs/parity/mir-fork-community-patches.md`.
- **Test baseline:** fulltest **572 / 0 / 0 / 18** (exit 0, both check gates
  GREEN), gcc.c-torture **1567 of 1652 in-scope (95.0%)** at `-O1` *and*
  `-O2`, MIR `make test` green with 3 new regression tests, SMAUG 1.8 boots.
