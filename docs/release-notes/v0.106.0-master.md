# madc v0.106.0

**Table-driven unwinding, self-describing modules, C++ conformance — and plain
C programs that need nothing but the C library.** Everything since v0.105.0: a
throw now unwinds through the platform's own unwinder on every target MIR
supports; markdown, git and the web UI become modules a program imports by
name; a C program madc builds names only the C library, so issue #8's Lua
parser drops from 10.1 MB to 1.6 MB peak memory; and madc compiles C about
1.8× faster than 0.105.0. madcide releases alongside as **madcide 0.9.0** and
Chthonia as **Chthonia 0.3.0**, both carrying madc 0.106.0.

## Features

- **A plain C program needs only the C library.** An executable madc writes
  now names only the libraries its imports reach, as gcc's `--as-needed` link
  does, and MIR's call helpers (by-value struct arguments, `va_arg`) ride
  inside the image instead of pulling in libmadc. A C hello-world on Linux is
  a 10 KB executable whose only dependency is `libc.so.6`; issue #8's 6,000-line
  Lua parser went from `libmadc`, `libstdc++`, `libgcc_s`, `libm` and `libc`
  at 10.1 MB peak memory to `libc` alone at 1.6 MB (gcc's build: 1.5 MB).

      madc -o lua53 lua53.c     # NEEDED: libc.so.6

- **Faster compiles, faster startup.** Against 0.105.0, the same sources
  interleaved: C files compile in 0.35–0.63 of the time (geometric mean over
  40 compiles 0.565×), C++ in 0.91–0.96, issue #8's `lua53.c` in 152 ms
  instead of 170; a hello-world executable starts in 12 ms instead of 21; and
  generated code runs 2% faster (0.978× over 19 benchmarks). Against gcc
  `-O2`, generated code runs at ~81% of gcc's speed (was ~78%).

- **SQLite builds and passes its tests.** SQLite 3.54.0's `--enable-all`
  `testfixture`, built by madc, passes `veryquick.test` with the same two
  failures out of 394,060 as the gcc and clang builds. Its amalgamation
  compiles at `-O2` in 3.2 s — gcc takes 16.8 s, clang 15.7 s.

- **Exceptions unwind through the host's own unwinder.** MIR describes every
  generated frame as DWARF CFI and writes unwind tables into ELF, PE/COFF and
  Mach-O images, opening an unwind region per automatic cleanup variable, so a
  throw destroys the live objects of every frame it crosses — on x86-64,
  aarch64, ppc64, riscv64 and s390x, through `RtlUnwindEx` on Windows and the
  Apple arm64 unwinder on macOS. The unwind personality rides inside the
  image, so on Linux a C++ program with destructors needs no madc library and
  a madc object links with plain g++.

- **Exceptions behave as C++ says.** A class-type exception is owned by its
  throw and matched by type in each handler; a local object thrown from inside
  a `try` is moved, not copied ([class.copy.elision]/3); a try block left by
  `return`, `break`, `continue` or `goto` ends its frame; and a return reads
  its value before the scope's cleanups run.

      try { Widget w; throw w; } catch (Widget &x) { }   // moved, not copied

- **Capabilities become modules imported by name.** markdown, git and the web
  UI target are no longer wired into the core: `import markdown;`,
  `import git;` and `import ui_web;` open self-describing modules found on the
  module path (the program's directory, `--module-path=<dir>`, then madc's
  own). `--import=NAME` imports one ahead of the program — with no source it
  only answers whether the module is installed — and madc.ini's
  `modules = NAME` imports instead of linking.

      import markdown;
      var doc;
      markdown::parse(doc, "# hi");      // the document as a tree of nodes

- **One command line, read the way gcc reads it.** An unknown option is an
  error with a "did you mean" suggestion; `@file` response files expand; `--`
  ends madc's options; `-std=`, `-dumpmachine`, `-l`/`-L`/`-Wl,-rpath`,
  `-fPIC`, `-E -o` and gcc's `-W` warning selection are accepted; several
  sources on an artifact lane build as a project; and `--help=json` and shell
  completion scripts come from the same option table.

      madc -fPIC -Wall @flags.rsp foo.c bar.c -o prog

- **Virtual functions take one vtable slot per signature.** Overloads of one
  virtual name each get their own slot in declaration order, as the Itanium
  ABI lays them out, so overriding one overload no longer redirects them all.

- **Templates and traits resolve per instantiation.** A member template's
  placement new constructs at a typed address; a constructor template's
  mem-initializer and forwarding-reference instances answer per argument;
  `__is_same` / `std::is_same` answer type identity; and the class-property
  traits answer a cv-qualified class for its unqualified type.

- **The release pack gains a C layer.** The standard C headers are frozen a
  second time, under C, so a `.c` compile binds them instead of parsing them;
  system headers bind correctly across nested re-entry, `#include_next`,
  bound using-declarations, `#pragma push_macro`, and a `-D` no frozen header
  spells.

- **Dialect faces for paths, project manifests and the configuration
  directory.** `madc::path_generic` and the path extension/stem/parent faces,
  the project-manifest reader and writer, and one user-configuration-directory
  rule (with a Windows `%APPDATA%` arm) — so a host such as madcide calls
  madc's own code instead of carrying a copy.

## Fixes, internals and infrastructure

- **C correctness.** A function designator not followed by `(` is its address;
  an undefined weak reference links with a null address and an executable with
  an undefined reference is refused, as ld does; an object may be aligned
  beyond 16 bytes; a statement expression yielding no value is void; a tag a
  parameter list names first is declared at file scope; the middle operand of
  `?:` is a whole comma expression; `T *const p` no longer refuses writes
  through `p->m`; `__builtin_frame_address` / `__builtin_return_address`
  return the function's own; `__DATE__`, `__TIME__` (honouring
  `SOURCE_DATE_EPOCH`) and `__TIMESTAMP__` are right.
- **C++ object lifetime.** `delete` evaluates its operand once and runs the
  destructor of a class with an implicit non-trivial destructor or a
  cv-qualified pointee; a class-type array member is constructed, destroyed
  and copied element by element; the implicit copy assignment assigns every
  base and member through its own; a prvalue returned through the hidden
  result slot constructs its virtual bases.
- **Windows.** PE/COFF images carry unwind tables, a `try` unwinds through
  `RtlUnwindEx`, MIR probes the stack a page at a time, module DLLs export
  their namespace symbols, and the release set carries its modules where madc
  looks for them.
- **macOS.** Mach-O objects and executables carry unwind tables; `long double`
  is 8 bytes on Apple arm64 (16 on Intel, as clang); the prelude honours
  `NDEBUG`; `-static-libmadc` covers the libSystem directory; JIT frames are
  registered with the Apple arm64 unwinder.
- **MIR.** Builds for ppc64, riscv64 and s390x hosts again; every function and
  innermost loop head starts a 32-byte block on x86-64; c2mir's built-in
  `<stddef.h>` defines `NULL` on every x86-64 target; instruction patterns are
  indexed with one counting sort for every target.
- **Front-end speed.** Vector-backed expression stacks, interned-name
  comparisons in the hot parser and CIR paths, kind accessors in place of the
  hottest `dynamic_cast`s, and a faster lexer inner loop.
- **Process.** Every release now moves C23 or C++20 conformance forward
  (c23-run 35 → 40, torture-c23 1490 → 1493 this release) and reduces existing
  duplication, each gated; a release archived without its callgrind map cannot
  reach master.
