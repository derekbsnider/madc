# Release v0.78.0 — 2026-08-12

The torture window closes. The five gcc.c-torture regressions that
crept into the 2026-07-23→08-11 window — all standard-C class-(a)
shapes — are root-caused and fixed, restoring the 1614 baseline
byte-for-byte and re-meeting the promote gate. Each fix ships with a
gcc+clang-oracled reducer in the suite, and the Windows release lane
(Track 6.4) is now planned end to end.

- `long double` struct members align 16 (SysV x86-64): the
  `DataDefLDOUBLE` override its own comment promised — madc's
  parse-time layout had disagreed with c2mir's runtime layout (24 vs
  32 bytes for the same struct).
- `__builtin_classify_type` is a real parser builtin, folding GCC's
  typeclass constant from the unevaluated operand's type. It was a
  lexer macro expanding to 0, so classify-gated code always took the
  wrong branch.
- An anonymous aggregate keeps its inline-body emission even after a
  nested named type promotes it to class-hood — it previously emitted
  a `struct __anon_N` reference no one ever defines.
- A nested brace list in a designated initializer aggregate-initializes
  a class-promoted member recursively ([dcl.init.aggr]p12) instead of
  posing as a constructor argument; plain-struct members' inner braces
  become compound literals typed from the member.
- gcc.c-torture: **1614/1/9/0/61**, byte-identical to the 2026-07-23
  green baseline; the failset is again exactly the 10 classified
  class-(b) GNU-extension items. Integration suite grows to **1023**
  (four new oracle-backed reducers).
- The Windows release lane plan lands
  (`docs/plans/2026-08-12-windows-release-lane.md`): mingw-w64 +
  libstdc++ + UCRT, Win64 only, full-suite scope (JIT, AOT `-o`,
  `--obj`, emitted C, packed groves), validated natively on the
  Windows 11 host that carries the build container.
