# Release v0.85.0 — 2026-08-18

`php::print_r` and `php::var_dump` over **any** madc type. The compiler is their
implementation — they are declared in `<ns_php>` with no definition anywhere, and
the CIR builder generates a dumper for whatever type the argument has — so a
program that never dumps carries nothing, and no runtime type-descriptor table
exists. php-cli 8.3.6 is the oracle, captured with `cat -A`, and every shape PHP
can express is byte-identical to it.

The arc closes here: **all 20 probe shapes render**, and the one remaining
refusal is a limit that names itself rather than a gap. Getting there also
uncovered FIVE silent wrong answers in the compiler, each of which is fixed with
its own reducer and gate — including a pointer comparison that answered the wrong
thing whenever a secondary base was involved.

- **Aggregates, arrays and positional containers.** A struct, a class with
  private and protected members, a base-flattened derived class, a union, an
  anonymous union, a bit-field, a fixed and a multidimensional array, a `char[]`
  as text, and `std::string` / `std::vector` / `std::array` — each with PHP's own
  indentation, its `[prot:protected]` and `[priv:Foo:private]` keys, and the blank
  line after a nested block. `var_dump` makes exactly one deliberate change: it
  names the REAL C/C++ type, spelled the way the SOURCE spells it
  (`std::string`, never `std::__cxx11::basic_string<char,…>`).
- **Pointers are FOLLOWED**, at the same depth, because an indirection is not a
  nesting level. A ring, a self-pointer and a mutual ring end in PHP's
  `*RECURSION*`; a value reachable twice WITHOUT a cycle prints in full both
  times, which is what PHP does. It is an ancestor STACK, not a visited set, and
  keyed on (address, pointee TYPE) — without the type,
  `struct T { int v; int *p; }` with `p = &t.v` reports a false cycle. The pointee
  walk is a generated FUNCTION and the recursion is a call, which is why a
  5000-node list prints in full and a 14-level fan-out graph compiles in half a
  second.
- **Enums name their enumerator**, in PHP 8.1's own enum shape, with the real
  backing type in the head word. A value naming no enumerator — legal C, no PHP
  form — shows an empty `[name]` rather than inventing a case.
- **`std::map`, `std::set` and `std::list` render**, through C++'s own iterator
  protocol. A keyed container prints `[key] => value` and never the `std::pair`
  its elements are; keyed is decided structurally (the container names a
  `mapped_type`), so a set and a list print positionally like a vector. The
  recognizer is SHARED — **the range-based `for` is its second consumer, so
  `for (std::pair<const int,int> &kv : m)` works now too** — and it covers a
  hand-rolled container as readily as a standard one, with either a class
  iterator or a raw-pointer one. The loop is COUNTED off `size()` because
  libstdc++ declares the iterator's `operator!=` as a friend FREE function, so
  there is no member to dispatch; that is why a container with `begin()`/`end()`
  and no `size()` is the one permanent refusal, and it says exactly that.
- **`array` / `value` print across all nine kinds** through one runtime walk,
  with `var_dump` naming the KIND — a dynamically typed slot's real type IS its
  kind, and no C word distinguishes `string` from `bytes`.
- **`print_r($v, true)` captures the text**, with PHP's real signature: one
  function, a defaulted second parameter, and a `string|true` return that maps
  onto madc's `value`. The flag may be a runtime expression, because the output
  sink is a parameter rather than a compile-time choice.
- **Fixed: a type that contains ITSELF expanded forever.** A container whose
  element type is the container — legal C++, a JSON-tree shape — consumed 4 GB and
  died with `std::bad_alloc`. The guard is an ancestor set in the TYPE domain, the
  compile-time analogue of the runtime one the pointer walk uses, and a PATH set
  rather than a visited set so a struct with two members of one type still prints
  both.
- **Fixed: a pointer comparison against a base subobject omitted the base
  adjustment.** `B2 *p2 = &d; p2 == &d` answered 0 where g++ and clang++ answer
  1. For a primary base the addresses coincide, so it looked like a mere warning;
  for a secondary base the answer was silently wrong. libstdc++'s own
  `_List_base::_M_clear` is that shape, so every program using a `std::list` was
  affected.
- **Fixed: a `madc::value` member was misaligned and the -O2 lane crashed on
  it.** `DataDefARRAY` reported alignment 1 for a 48-byte 16-aligned object, so a
  member landed at offset 4 where both compilers place it at 16 — invisible at
  -O0, a SIGSEGV in the packed lane where `operator=` uses an aligned SSE move.
- **Fixed: a `madc::value`'s base type fell through to `int`**, so `value *p`
  emitted `int *p` — a four-byte declaration of a forty-eight-byte object.
- **Fixed: `class_nullary_call` could call the wrong overload** — it resolved the
  method by name and the symbol by name again, taking the first match each time,
  which for prefix vs postfix `operator++` is a coin flip.
