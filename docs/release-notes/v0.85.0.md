# Release v0.85.0 — 2026-08-17

`php::print_r` and `php::var_dump` now work over **any** madc type, not just
`array` / `value`. The compiler is their implementation: they are declared in
`<ns_php>` with no definition anywhere, and the CIR builder generates a dumper
for whatever type the argument has. Every shape PHP can express is byte-identical
to php-cli 8.3.6, and `var_dump` makes exactly one deliberate change — it names
the real C/C++/madc type instead of simulating PHP's.

- **`php::print_r(v)`** renders a struct, a class with private and protected
  members, a base-flattened derived class, a union, an anonymous union, a
  bit-field, a fixed array and a `char[]` the way PHP renders the corresponding
  value: the 4-space entry indent, the 8-space step of a nested `(`, the blank
  line after a nested block, `[prot:protected]` and `[priv:Foo:private]`, `1` for
  `true` and the empty string for `false`.
- **`php::var_dump(v, ...)`** is variadic like PHP's, keeps PHP's frame (2-space
  indent, key and value on separate lines, `}` with no trailing blank line), and
  names the REAL type: `int(42)` / `long(42)` / `unsigned int(...)`,
  `double(3.5)` / `float(1.5)`, `char *(2) "hi"` / `char[8](2) "hi"`,
  `struct Point(2)` / `union U(2)`, `int[3](3)`, `std::string(2) "hi"`,
  `std::vector<std::string>(2)`.
- **A type is named what the SOURCE calls it.** `std::string`, not
  `std::__cxx11::basic_string<char,std::char_traits<char>,std::allocator<char>>`.
  That comes from inverting madc's own type-name tables by type identity — a
  `typedef` binds a spelling to the DataDef it names — and never from matching
  `basic_string` as a string. A container adds its element type (which is
  `operator[]`'s return type, the same one the walk dumps) and drops the defaulted
  allocator and traits: `std::vector<int>`.
- **Positional containers work — the owner's own two examples.** A
  `std::vector<int>` prints exactly the way PHP prints an array of ints, a
  `std::string` prints as its text, and a `std::string` member inside a struct
  does the same. One structural test decides it (the type-checked
  `size()`+`operator[]` protocol the range-for shares) plus the element type: a
  sequence of characters is text, anything else is an array. No container name,
  `c_str` or `length` is matched anywhere.
- **A double carries PHP's 14 significant digits**, including the `.0` mantissa
  PHP puts in an exponent form (`1.0E+25`) that C's `%G` drops.
- **The walk never computes — or even reads — a layout fact.** Members are
  emitted as `obj.member` access nodes, so bit-field shift/mask,
  anonymous-aggregate transparency and base flattening keep their single owner.
  Arrays get a real loop, never an unrolled one.
- **Refusals are by name of the type, never a guess.** Pointers, enums,
  associative containers, multidimensional arrays and `value` itself each report
  `no dumper for type 'X' yet` until their slice lands.
- **Not exportable, structurally.** A declared-but-undefined template is an
  unresolved symbol for any C++ host that calls it — the intended contract, and
  the first deliberate exception to `cpp-first-api.md` (documented there).
- **A range-for crash fixed on the way in.** `for (int v : std::map<int,int>)`
  SIGSEGV'd at (nil) where g++ and clang both reject the source: the iteration
  protocol matched `size()`/`operator[]` by NAME and handed the loop counter to
  `map::operator[](const key_type &)`, a pointer parameter fed an integer. The
  match is type-checked now, and the element accessor delegates to
  `class_subscript_addr_on` — the one `operator[]` call builder — which also
  fixed a second live crash on a container whose positional `operator[]` takes
  `const long &`.
- **The runtime is ledger-registered** (`src/rt/rt_dump.c`, strict C11), so a
  `-static-libmadc` program that dumps links on Mach-O too, where there is no
  dylib fallback. Verified on JIT, `--exe`, `--obj` and `--emit=c11` → `gcc`.
- **`php-cli` is now provisioned** (`scripts/provision_container.sh`): it is an
  oracle, like `g++` and `clang++`, and its absence would have read as green.
