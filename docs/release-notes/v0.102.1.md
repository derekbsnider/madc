# Release v0.102.1 — 2026-10-07

**The bug-fix release for v0.102.0.** v0.102.1 began as the Ubuntu 24.04
packaging patch and grew into the bug-fix release, carrying every fix banked
since v0.102.0. madcide gains autoindent; aarch64 and macOS executables that
define variadic functions link and run; macOS images with large zero-filled
data load; aarch64 passes floating-point aggregates per AAPCS64; a Windows GUI
program run with `--tui` gets a usable console; and the `.deb` built on
Ubuntu 24.04 opens its windows under AppArmor.

## Highlights

- **madcide autoindent.** Enter copies the current line's indentation, one step
  deeper after a block opener (`{` for C/C++/madc, `:` for Python); a `}` typed
  first on a blank line dedents one step, and one undo takes back both the
  dedent and the character. The indent level is each buffer's own, read from
  its file (tabs, or the spaces it most often steps by; a file with no indented
  line yet uses its language's default). On by default; Edit ▸ Toggle
  Autoindent (the `I` row of `^T` Options) turns it off and keeps the choice in
  settings.json.
- **macOS and aarch64 variadic executables link and run.** A program that
  defines a variadic function reaches libmir's `va_arg` / `va_block_arg`, now
  exported on ELF and Mach-O; before, such an executable failed to link on
  aarch64 Linux and aborted at launch on macOS (exit 134). A program using
  `int`, struct, long double and 160-byte by-value `va_arg` prints `3 6 6 6.25`
  as gcc does on the Mac mini and the Intel MacBook.
- **macOS images with large zero-filled data load.** A native Mach-O image
  whose zero-fill `__DATA` (bss) reached past its data's file pages placed
  `__LINKEDIT` inside the bss range, and dyld refused it — killing an executable
  at load and failing `libmadcide.dylib`'s open on Intel macOS. The extra
  carrier and `__LINKEDIT` now start at `__DATA`'s memory end as in ld64's
  layout, so the image loads.
- **aarch64 passes floating-point aggregates per AAPCS64.** aarch64 passes and
  returns homogeneous floating-point aggregates in consecutive FP registers
  (results in v0–v3), with a `_Complex` argument carried whole as a two-member
  HFA; before, c2m-compiled and natively compiled code disagreed on every such
  aggregate. Validated against gcc on aarch64 Linux and under qemu.
- **A Windows GUI program run with `--tui` gets its console.** A GUI image
  (built `-mwindows`) run with `--tui` from a Command Prompt refused the
  terminal UI because its attached console's streams were reopened write-only;
  they now reopen read/write, so the terminal UI opens.
- **MIR codegen and c2mir fixes.** An inlined call's by-value-struct argument
  copy is released each execution (a struct passed in a loop no longer grows
  the stack); four upstream varargs/inlining fixes from Cyan Ogilvie are
  adopted; `c2m` no longer crashes under `-pedantic` and reads errno correctly
  on a number's range check; an `_Alignas` on a struct or union member parses;
  and MIR compiles itself on aarch64 without depending on plain char's sign.
- **The Ubuntu 24.04 `.deb` carries an AppArmor profile.** Ubuntu 24.04 and
  later deny an unprofiled program the user namespaces WebKit's bwrap sandbox
  needs, so on a native 24.04 desktop a madc window died at its first rendered
  page with SIGTRAP (exit status 133, LP: #2046844); WSL, containers and 22.04
  do not restrict them. The `.deb` built on 24.04 and later installs
  `/etc/apparmor.d/madc` (unconfined + userns for `/usr/bin/madc` and
  `/usr/bin/madcide`), loaded by postinst, and `package_install_gate.sh
  apparmor` proves the window stays up 15 s with the restriction on.
- **Release assets named as GitHub stores them.** GitHub writes a `~` in an
  asset name as `.`, so v0.102.0's `SHA256SUMS` mismatched its `.deb` names;
  the release now renames the debs before checksumming, and the published
  v0.102.0 `SHA256SUMS` was re-uploaded with the GitHub names. One `.deb` per
  Ubuntu release makes 10 assets.
- **Release tooling no longer stales the test lanes.** A packaging,
  release-archive or gate script change shares nothing with the source the test
  suite runs; the lane ledger now excludes that tooling from a lane's content.
- **Chthonia's relation corrected.** Chthonia is its own product, in its own
  repository, whose packages each carry their own madc release; nothing is
  installed from madc for it.
