# Release v0.15.0 — 2026-05-17

GCC torture test suite parity initiative. The pass rate nearly doubled from 627/1685 (37%) to 1245/1685 (74%) through 96 compile-failure fixes across the parser, lexer, compiler, and type-safe arithmetic layers. A new `scripts/run_gcc_testsuite.py` runner drives the GCC `gcc.c-torture/execute` suite as an ongoing parity benchmark.

## Highlights

- **GCC torture tests: 627 → 1245 (37% → 74%)** — 96 compile failures closed, 22 newly compilable tests now reaching runtime
- **C comma operator** — `(expr1, expr2)` evaluates left for side effects, returns right
- **Full `#if` evaluator** — integer arithmetic with proper C precedence (was boolean-only)
- **Scientific notation** — `1.5e-3`, `1e5`, leading-dot `.5e3` with F/L suffixes
- **Mixed int*double arithmetic** — C99 usual arithmetic conversions for `*` operator
- **K&R function semantics** — `f()` accepts any args, `f(void)` means zero; applies to function pointers too
- **Bitfields in anonymous structs** — named, unnamed, and comma-separated members
- **50+ `__builtin_*` aliases** — math, string, va_arg, signbit, classify_type, bswap
- **`#error`/`#warning` directives**, `__attribute__` consumption in 6 new positions, `_Alignas`
- **Flat struct init**, forward enum refs, zero-length arrays, `typedef const struct`

## Test Baseline

- Integration: 542 passed, 48 failed
- Unit: 80 datadef + 24 IR + 5 error passed; libmadc_program has pre-existing native EXE failures
- GCC torture: 1245/1685 (74%)
