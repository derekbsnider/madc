# Release v0.99.0 — 2026-09-08

madcide is a desktop application. The GUI chrome milestone (S0–S5) turns
the window that used to show the terminal's composed tree into real
application chrome: a native menu bar fed by one command/menu data file, a
status bar of discrete themeable items, native Open / Save As dialogs, the
JOE split rendered as a window stack, and a mouse that places the caret
and drags a selection — all through the one composer and the one client
loop the terminal uses, so the TUI is byte-identical. Underneath, the web
editor became incremental (a keystroke moves work proportional to what
changed), the ui event vocabularies became enums the compiler checks, and
four carrier defects the work uncovered were fixed at their layer.

Highlights:

- **The native menu bar (S1 + S2)**: `profiles/default.menu` is the ONE
  command registry + menu map (VS Code's contribution shape on the action
  vocabulary the key profiles bind; `[when]` clauses against the live
  context); the engine resolves each command's bound chord and hands the
  host the menu only when it changed; GTK4 draws it (`GtkPopoverMenuBar`
  through madc's `madcwebview_chrome` extension of the webview library); a
  selection is the chord's own action event. A fulltest gate keeps
  profiles, dispatcher and menu on one vocabulary.
- **Native file dialogs (S4)**: Open File / Save As are a core→client
  request/response verb — a `GtkFileDialog` in the window, JOE's prompts
  in the terminal and wherever a platform has no native dialog yet.
- **The status bar as chrome (S3)**: the JOE format's seats (file, modified,
  Row/Col, mode, chord echo, enclosing function) as discrete items with
  semantic classes, `@gui`-themeable.
- **The window stack (S5)**: the workbench places one slot per region and
  stacks a region's nodes; the `^K O` split renders as JOE's screen — a
  status line heading each window, fixed heights from the composer's own
  budget, the message line in the foot.
- **Resize over a remote display (S0)**: GTK's GL renderer paints black over
  a no-shared-memory TCP X connection (Docker → VcXsrv); the web target
  defaults `GSK_RENDERER=cairo` when `DISPLAY` names a host.
- **Mouse caret and drag-select**: the page hit-tests a gesture to a line and
  column, the engine resolves it to a byte offset over the rows it
  emitted, the editor core places caret and selection through ONE model;
  page columns are byte→string converted (multibyte text lands on the
  right cell).
- **The incremental web editor**: a newline index in the text buffer
  (`line_of` O(log n)), one start-sorted span sweep, and a per-key row
  basis with ONE splice per keystroke — navigation moves only the caret,
  the wire dropped from ~296 KB to ~700 B per keystroke.
- **Event vocabularies as enums**: `ui::key`, `ui::event_kind`,
  `ui::pointer_phase` in one shared text for the engine and the dialect;
  every event object carries the codes beside the names.
- **Carrier fixes found on the way**: `var &r = o["h"]` binds the live slot;
  `6 == v` / `v == E::z` compare by value (the reversed equality
  candidate); `c ? v : php::trim(p)` is a value prvalue materialized into a
  temp the selected arm assigns; a `var &` in a `%s` position coerces like
  a `var`.
- **`madc --capabilities=json`** (reworked from PR #7, with credit to its
  author): the machine-readable capability manifest, gated against the
  binary.
