# Release v0.99.2 — 2026-09-09

The owner's hands-on round on the polished local IDE, answered — the last
polish before the master GUI release. Five findings from the staged Windows
and Mac desktop builds, each fixed at its layer: a program run from the
window now streams into the Terminal tab with no keystroke, the Build menu
runs Build → Run with no overlay, a dialog's Close button closes it and
leaves nothing behind, and the bottom panel and sidebar are resizable. The
terminal is byte-identical throughout.

Highlights:

- **Output streams with no keystroke**: the window's wait is now the
  cooperative scheduler's bounded wait, as the terminal's always was — the
  engine fires what is due, hands runnable tasks the CPU and wakes the
  application between platform loops, and while tasks are parked it asks
  the host to end its loop after a few milliseconds (`tick`, a one-shot
  UI-thread timer on GTK, Cocoa and Win32). A program run from Build → Run
  (or a build's Output) appears as it happens; an idle window with no live
  task still blocks for free.
- **The Build menu carries every `^B` row** — Check, Build, Run, Run native,
  Stop, the project's rows and a manifest's own commands — as direct items,
  so Build → Run runs with no overlay. `Build…` keeps the palette for the
  keyboard; Check lives in the command palette.
- **A dialog's Close button closes it**: the `@pane` cancel posted by name
  reached the wrong dispatcher region and came back as an unknown action.
- **A closed dialog leaves no furniture in the panel**: the page re-uses a
  node's element when the tree shifts into its position, and a kind change
  now clears the old kind's title, rows and buttons before it draws.
- **Resizable panel and sidebar**: drag the splitter over the panel's top
  edge (or the sidebar's right edge); a double-click on the panel's
  splitter maximizes it and back; the window remembers the sizes.
