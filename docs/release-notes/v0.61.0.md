# Release v0.61.0 — 2026-07-29

The stdlib-flavor switch (task #16, P2.3): madc's std:: inline ABI namespace
now follows the PARSED stdlib configuration, and native-emit DT_NEEDED
follows the active `-stdlib=` flavor — never a host `#ifdef`, never a
hardcoded literal. This unlocks the libc++ native legs: `--exe`/`--obj`
grow 780 → 782.

Highlights:

- The ABI namespace comes from the config macros each stdlib defines for
  exactly this purpose: `_GLIBCXX_USE_CXX11_ABI` (libstdc++, 1 ⇒ `__cxx11`
  on the cxx11-tagged components) and `_LIBCPP_ABI_NAMESPACE` (libc++, e.g.
  `__1`, on every component) — pushed into the mangler the moment the parsed
  define is recorded, from all three define-write sites (directive, forest
  replay, CLI `-D`).
- All canonical std:: spellings, `itanium_mangle_std_var` (`_ZSt4cout` vs
  `_ZNSt3__14coutE`), and the `marshals_value_text` carrier follow the
  flavor; unit-gated against the clang++-18 `-stdlib=libc++` oracle,
  including the pre-C++11-ABI `Ss` form.
- `cir_native_link_env` de-conflated: the C++ runtime DT_NEEDED set is the
  flavor's own, probed at build time from its toolchain's empty-program
  link (no flavor→SONAME table); `#ifdef __APPLE__` remains purely the
  Mach-O/libSystem platform arm. A `-stdlib=libc++` emit links
  `libc++.so.1`/`libc++abi.so.1` and runs.
- `testcommontype_libcxx` and `testdestructible_libcxx` now pass the
  `--exe` and `--obj` lanes end-to-end (their `.exe_skip` gates removed).

Suites: fulltest 798/0/0/9; `--exe` 782/0; `--obj` 782/0; packed arbiter
798/0/0/9. MIR fork unchanged (1.0-madc.0.52.0).
