# Release v0.43.0 — 2026-07-25

The aarch64 cross-AOT release: Mach-O/ARM64 track axis A is complete.
`bin/madc-aarch64-linux` — an emit-only cross compiler in the gcc mold —
produces aarch64 ELF executables, relocatable objects, and multi-object
merges from an x86-64 host, with MIR as the cross
compiler/assembler/linker (no external toolchain), proven end-to-end
under qemu-aarch64. Ships with MIR fork release 1.0-madc.0.43.0.

- `make -C src cross-aarch64-linux` builds the emit-only cross binary
  against the fork's `build-aarch64-linux/libmir.a` variant; every run
  lane refuses loudly, every emit lane works.
- Fork: `mir-target.h` build-time target selection (arch/OS knobs +
  pair helpers + validation; no override = host detection,
  upstream-identical), and the full aarch64 AOT object-capture: PIC
  addrpool model (`adrp+ldr`/`adrp+add` against `.mir.addrpool`),
  three new bias-invariant reloc kinds mapped per target at every
  writer seam, an aarch64 `_start` stub, 64K max-page-size, and a
  target-gated `.debug_frame` CIE.
- Gate A evidence (all-Linux): pure C `-o` output matches the
  `aarch64-linux-gnu-gcc` native reference (stdout + exit code); the
  system linker independently validates our relocations on `.o`s;
  `.mad` `-o` and the `-c` → madc-link → PIE merge lane run correctly
  under qemu-aarch64.
- Eval-shim gating: standalone executables (and all non-`-shared`
  cross artifacts) skip the `__madc_shim_*` host-call adapters, so
  pure programs emit runtime-free — no `libmadc.so.0` dependency.
- `c2mir`'s `mir_ldouble` is target-conditional: `double` for
  arm64-macos (layout correctness), size-correct binary128 for
  aarch64-linux (fold precision host-bounded, documented).
- Host regression battery unchanged and green: fulltest 754/0/0/9,
  exe 738/0, obj 738/0, packed 754/0/0/9.

Next: axis B — the Mach-O writer + in-emitter ad-hoc code signature
(the `/promote` milestone gate).
