# Release v0.99.1 — 2026-09-08

The owner's first round with the v0.99.0 desktop application, answered: the
prompts are dialogs, a click picks the window, and the status bar looks like
chrome. The terminal is byte-identical throughout — every change is data the
composer stamps on the same tree the terminal renders, plus the page that
draws it.

Highlights:

- **The prompts as dialogs**: every bottom-line prompt — find, go to line,
  insert file, theme, tab width, the colon line, the project add — floats in
  the window as a QUICK INPUT (the label over a field showing the text the
  core holds, a caret, the keys it answers to); the quit question on a dirty
  buffer is a CONFIRM dialog with Yes / No buttons. The core keeps owning the
  input (Neovim's `ext_cmdline` shape): a key reaches the prompt exactly as
  in the terminal, the page only draws it. A button, and a press outside the
  quick input, posts the modal scope's ACTION by name — the menu-bar rule —
  and the prompt arms admit an action the `@confirm` / `@prompt` scope binds.
- **A click picks the window**: with two-plus windows, a press in another
  window's text activates it and places the caret; a press on a window's
  header activates it with its caret kept. Every window's edit node carries
  its window index as a `tag` the pointer event echoes — the one answer when
  the `^K O` split shows one document twice.
- **The status bar looks like chrome**: the proportional chrome font on its
  own surface, the file name leading, caption labels, accent pills for the
  modified / read-only badges, a key cap for the pending chord, tabular
  digits; the active window's header marked. Themeable through `@gui`.
- **`(^C aborts)` is true**: a modal scope consults an action event's
  sequence, so JOE's `^C` (the bound `discard`) ends a prompt as the label
  promises — baked as data (`@prompt ^c pcancel`), in every profile.
