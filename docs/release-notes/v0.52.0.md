# Release v0.52.0 — 2026-07-26

`madc -c` for a Mach-O target now writes a **real relocatable object** —
one Apple's own linker accepts and links correctly — and madc reads one
back, so every `.o` lane madc has on ELF works on darwin: compile, link,
the multi-object merge, and `-r`. That completes Mach-O axis B, and it
leaves the fork with one merge implementation behind two container fronts
rather than a second copy of the linking logic.

- **`MH_OBJECT` emit.** One unnamed `LC_SEGMENT_64` over the same section
  names the executable writer uses (`__TEXT,__text`, `__DATA,__data`,
  `__DATA,__bss` zerofill last, `__DATA_CONST,__mir_addrpool`,
  `__DATA_CONST,__mod_init_func`), a real `LC_SYMTAB`/`LC_DYSYMTAB`, and
  per-section `relocation_info` arrays. Until now a darwin `-c` wrote an
  ELF `ET_REL` — a documented interim that madc's reader consumed but no
  Apple tool could.
- **`ld64.lld` links it**, against the macOS SDK, including a **mixed
  link** where a clang-compiled TU calls into the madc-compiled one.
  Apple's linker resolves the relocations to the right targets: pool slots
  land inside `__text` and `__bss`, imports become dyld binds.
- **Mach-O merge read-back.** `MIR_object_read` gained a Mach-O front, so
  `-c` → link, the two-TU merge and `-r` (two `.o` → one) all work for
  Mach-O targets, and the merged `.o` stays linkable by both madc and
  `ld64`.
- **Read-back is proven equivalent, not merely plausible:** the `.o`
  path's image disassembles *identically* to the direct `-o` emit, pool
  contents included. That leg caught a real bug — Mach-O has one
  `ARM64_RELOC_PAGEOFF12` where ELF has two kinds, and the opcode sniffing
  that recovers the kind dropped the `sf` bit, reading every
  `add Xd, Xn, #imm12` back as a scaled load.
- **One merge, two fronts.** The reader now works off a format-neutral
  input view (section bodies, symbols, relocations, debug) filled by an ELF
  or a Mach-O front — compile-time exclusive, one target per compiled
  stack — instead of duplicating the symbol-unification and rebasing logic.
  ELF behavior is unchanged.
- **`-g` on a Mach-O target says so once**, at the layer the user typed it,
  and continues without debug info — replacing the executable writer's
  silent drop of an attached debug builder.
- **New gate: `make -C src machogate`** — 30 assertions, 15 per arch, over
  two independent authorities (`ld64.lld` + the SDK, and madc's own
  round trip). The target rebuilds both cross madcs first, so the gate can
  never validate a stale binary.
- **Unblocked:** `-static-libmadc` in the `.o` link lane now has its fork
  prerequisite; what remains there is madc-side cover analysis.
- Running an emitted Mach-O binary remains the owner's Mac, as in every
  darwin slice. The in-process `.o` loader on Apple hosts refuses loudly
  until it gets both the Mach-O parse and `MAP_JIT`.
