# Release v0.106.1 — 2026-10-24

A patch release fixing two Windows regressions in 0.106.0. Neither changes
what madc compiles or how fast: on Windows, a library Run no longer prints a
pack-writer report on stderr, and the Windows release build works in a fresh
tree.

Highlights:

- **A library Run on Windows is quiet again.** On Windows, `madc::parse_run`
  (madcide's Run) freezes the live parse to a temporary snapshot before it
  runs the program. For a program that includes a system header, 0.106.0's
  pack writer printed `madc: pack spelled names: frozen unit N (...) carries
  no source text — the table is left out` on stderr every time. The writer's
  informational reports now print only when the freeze asks for progress, as
  its "Froze ..." lines already did, and a Run's freeze does not ask.
  `testparserunfrozen` gains a guest that includes `<stdio.h>` and requires
  an empty stderr.
- **`make -C src release-windows` works in a fresh tree.** The hosted Windows
  build reads the dialect's and the modules' generated tables from the host's
  dev madc. The target now builds that madc first, as `release-macos`
  already did. Before, a tree with no `bin/madc` (the release workflow's
  runner) stopped with `No rule to make target '../bin/madc'`.
- **Release gates for a patch release.** A patch release (x.y.Z, Z > 0) is
  measured and may lower no C23 / C++20 conformance count, but needs no rise
  and no consolidated duplicate family. Both release-gate scripts carry a
  patch control each way.

madcide 0.9.1 and Chthonia 0.3.1 ship alongside, carrying madc 0.106.1.
