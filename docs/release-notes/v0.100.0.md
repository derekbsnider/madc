# Release v0.100.0 — 2026-09-21

The Nexus release. madcide stops being a desktop application and becomes a
*session* — many clients, several transports, and no display at all if you
want none — while the live IR becomes a node-addressed graph an agent queries
and edits through validated verbs instead of text patches. Alongside it, C++
conformance stopped being an assertion: the measurement was built, published,
and then driven from 60% to 75.1% against gcc's own testsuite. 555 commits.

Highlights:

- **A window is a client.** One cooperative loop serves N clients over the
  same document. A second window is a second client with its own caret and
  its own View; presence carets shift through one anchor registry as anyone
  types, and render identically in the terminal and the web face.
- **Views and containers.** The editor region is a real split tree, tool panes
  are chrome slots, and layouts persist beside the project manifest. A View
  re-represents the same document as source, MC11, C11 or C++ *in place* —
  source left, MC11 right, carets tracking each other through the emitter's
  correlation map.
- **Every change is an event.** An append-only journal whose buffer text is
  both the persisted form and the wire form, with replay to any point,
  checkpointing, compaction, and an `event:N` history View.
- **Transports, one process, several faces**: an `api` transport with
  permission tiers, a headless `--serve`, an RFC6455 `ws` window on the same
  port, an MCP seat, an LSP face, a VS Code extension, an attach relay and
  session discovery.
- **The Nexus (L1–L4e)** — the code-graph MCP: graph verbs over the **live
  IR**, node editing through validated verbs, PAST verbs over git history, a
  propose tier, intent records, asset layers and a test-runner seat. This is
  what makes madc's IR addressable by an agent rather than only by a compiler.
- **The async I/O reactor gained a Windows backend** (WSAPoll), lifting 15
  Windows skips; and **libgit2 was demoted from a vendored subtree to the
  `madcgit` module** — a dependency, not a distribution.
- **Itanium ABI compatibility.** Every C++ symbol madc defines now emits its
  real mangled name, so a madc object file links against g++- and clang-built
  code and free functions overload by parameter type; by-value class
  parameters and returns follow the Itanium calling convention.
- **C++ language work**: expression SFINAE, pointers to members (types and
  values), real lambda capture lists including `mutable` persisting across
  calls, inheriting constructors, references binding prvalues with correct
  destructor timing, `thread_local`, and fourteen hand-rolled declarator
  readers consolidated into one owner.
- **Conformance is measured, not claimed.** The `g++.dg` ratchet lane was
  built in this window and driven **1169 (60%) → 1464 / 1950 (75.1%)** with
  zero failures outside its baseline. Every measurable standard is published
  in [`docs/conformance-coverage.md`](../conformance-coverage.md): C at 99.2%
  of the in-scope gcc c-torture set under `--std=c17` and 220/220 on
  c-testsuite; C++98 80.0%, C++11 75.1%, with C++14/17/20 alongside.
- **Three standard-C regressions found and fixed** by that coverage work — a
  `static` prototype reading as a signature clash, an unprototyped declaration
  compared as a prototype, and a compiler SIGSEGV on a cast through a
  `const`-qualified struct pointer. gcc c-torture returns to **1611/1624 with
  zero regressions** against the v0.99.2 binary. The suite had drifted for
  five weeks because it was a 25-second run nothing owned, so suites are now
  **tiered by time to run**: the fast tier gates every commit, the long lanes
  gate merges.

Every platform lane is green on one commit: the linux battery (JIT 1540/0,
exe/obj 1444/0, packed 1540/0, headerless 1506/0), the libc++ flavor lane
(1533/0, exe/obj 1437/0), genuine Windows 11 and Wine (1480/0 each), the macOS
suite on both runner architectures (arm64 1520/0, Intel 1521/0), c-testsuite
220/220, gcc c-torture 1611/1624, and the Xvfb GUI stage 19/19 across JIT, exe
and obj.
