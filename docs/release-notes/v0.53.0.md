# Release v0.53.0 — 2026-07-26

`-static-libmadc` now works in the **`.o` link lane**, lifting the last
stated boundary of the forest-carriers S5 track: a program linked from
precompiled madc objects can carry the madc runtime inside its own image
and run with no madc library present. The runtime enters as one more
relocatable — generated into a private object-mode context and merged in
through `MIR_object_read`, the read-back path both containers (ELF
`ET_REL` and Mach-O `MH_OBJECT`) already gate — so the slice needed no
new format code and no fork change at all.

- **`-static-libmadc` in the multi-object link lane.** The AOT ledger is
  carried as MIR modules, so the pieces a program needs are pulled into a
  private object-mode context, generated, emitted with
  `MIR_gen_object_emit`, and merged into the same builder as the `.o`
  inputs. Deliberately through the merge rather than generating into the
  input builder: a builder's symbol table is append-only, and the
  unification that turns the inputs' UNDEF entries into references to the
  runtime's definitions *is* the merge — one unification implementation,
  reused.
- **`-fno-eval-shims` — the build states its artifact is not
  host-callable.** Every `.o` carries a `__madc_shim_<sym>` adapter per
  host-callable function (the value-ABI surface a libmadc host calls
  compiled functions through), and those adapters import 12
  `madc_value_*` accessors, which are Tier B. An executable emit from
  source infers that nothing can call in and skips them; a `.o` cannot
  know, so the build says it — the shape `-fPIC` has. Objects compiled
  with the flag link runtime-free; objects that kept their adapters
  refuse, naming both the symbols and the flag.
- **The AOT-ledger carrier opens header-only.** The ledger is a
  container-global segment, but the probe ran `complete_open`, which
  binds the frozen string pool and arena into *live parse state* — so it
  died with "forest thaw requires a live string pool" in any lane without
  a lexer. The source lanes had hidden the layer confusion by always
  having a pool.
- **One cover analysis, two shapes of program.** The runtime-need
  classifier and the `-static-libmadc` verification take the reference
  LIST rather than its source: the source lanes pass the context's
  unresolved imports, the `.o` lane passes the merged builder's UNDEF
  names. Same classifier, same two diagnostics (no-carrier vs Tier-B).
  `cir_ledger_pull` likewise grew a seed list instead of a second pull.
- **Known boundary, now precisely stated:** `madc -static-libmadc
  -shared` refuses for the same Tier-B reason, because a shared object
  keeps its host-call adapters by design. The fix is the value-ABI family
  as Tier-A C11 in `src/rt/` — tracked, and the thing a self-contained
  *host-callable* plugin needs.
- **Gate:** `forest_ledger_gate` leg 9 flipped from asserting the refusal
  to proving the lane — two `-c` objects (one needing try/catch, one
  needing VLA scope exit, so a per-object merge cannot pass), the
  libmadc-linked baseline proved runtime-needing first and then used as
  the output oracle, a clean-machine run, the shim refusal naming symbols
  and flag, and `-static-libmadc -r` still refusing at the CLI.
- **Suites:** fulltest **756/0/0/9**, `--exe` **740/0**, `--obj`
  **740/0**, `machogate` **30/30** both arches, packed release arbiter
  **756/0/0/9**. Fork unchanged (**1.0-madc.0.52.0**).
