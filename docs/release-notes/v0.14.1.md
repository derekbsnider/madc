# Release v0.14.1 — 2026-05-10

**SMAUG native executables now survive the first real combat path.**
`smaug.exe` now boots, accepts telnet, completes character creation,
reaches Newgate room 109, enters combat with the serpent, survives
repeated damage rounds, and can kill the serpent cleanly in the
standalone native executable lane.

## Highlights

- **Small struct returns now match GCC and the SysV x86-64 ABI.**
  A 1..16 byte aggregate returned by value now comes back in `rax`/`rdx`
  instead of leaking a dead stack address or treating the first machine
  word of a local struct as a pointer.

- **The load-bearing SMAUG fix was `EXT_BV multimeb(...)`.**
  New-character login state depends on a small `EXT_BV` aggregate return.
  In native mode that value was corrupt, which pushed the runtime down a
  bogus `PLR_DENY` path and blocked even clean character creation.

- **The fix is validated in both minimized and real runtime form.**
  A standalone `multimeb` repro now matches GCC in both JIT and EXE
  mode, and the full `smaug.exe` probe advanced all the way through:
  login -> room 109 -> serpent combat -> serpent death -> loot.

## Validation

- `make -C src fulltest`
- `smaug.exe` runtime probe from `/tmp/smaug_run/area`
- Verified serpent combat and kill in room 109 on the native EXE path
