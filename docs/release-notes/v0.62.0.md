# Release v0.62.0 — 2026-07-29

The `<string>` frontier burn-down: libc++'s `<string>` header parses to
completion for the first time, its `__compressed_pair` storage core
compiles and runs correctly (including nonzero-offset base selection the
old lowering silently got wrong), and `std::numeric_limits` values are
exact under BOTH stdlib flavors. Six oracle-verified fix groups, eight new
gates; the suite grows 802 → 807 and the native lanes 782 → 791.

Highlights:

- Anonymous aggregates inside class templates resolve enclosing-class
  member typedefs — the last `<string>` parse blocker.
- `static_cast<Base&>(...)` member access works end-to-end: parse,
  receiver addressing, and a REAL derived-to-base subobject conversion
  (offset + type, vbase-aware) — a silent wrong-storage bug for secondary
  bases, fixed at the one existing owner.
- Constant-expression non-type template arguments (`f < sizeof(x) < a ?
  b : c >`) fold instead of desyncing the scanner to EOF — the hand-rolled
  angle counter the delimiter gate could not see is gone.
- `numeric_limits<unsigned long>::digits` is 64 everywhere: five stacked
  constant-fold defects fixed, including unsigned 8-byte cast semantics
  (libstdc++'s own answer was 63) and class-member aliases now shadowing
  same-named global classes per [basic.scope.class] (libc++'s real
  `__function::__base` was hijacking every local `__base` typedef).
- New debugging levers: `MADC_MAPWRITE_TRAP`, `MADC_STATCONST_PROBE`, and
  a diagnostics renderer that can no longer throw mid-error.
- The owner-set libc++ parity goal (behavior-parity, flavored suite lane
  as the finish line) is codified in the track plan and KG.

Suites: fulltest 807/0/0/9; `--exe` 791/0; `--obj` 791/0; packed arbiter
807/0/0/9. MIR fork unchanged (1.0-madc.0.52.0).
