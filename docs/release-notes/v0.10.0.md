# Release v0.10.0 — 2026-04-24

Typed-register IR scaffolding and the first three stages of bottom-up
migration. Stage 0 landed `IRBuilder` (load / store / coerce) and its
unit tests; Stages 1 / 2 / 3 collapsed ~880 lines of per-token shape
and coercion boilerplate out of `compiler.cpp` and onto fifteen shared
helpers, with zero behavior change. Three latent bugs surfaced and got
fixed as side effects of the refactor.

## Highlights

- **Stage 0 scaffolding.** `include/madc_ir.h` + `src/madc_ir.cpp` —
  `IRBuilder` with `load()` / `store()` / `coerce()`, `IRValue` carrying
  `(operand, DataDef, IRShape)` triples. Emit-as-you-build, no deferred
  graph. 23 new doctest cases in `tests/unit/test_ir.cpp`.

- **Stage 1 leaf-token sweep.** Every leaf token that produces a value
  (`TokenInt` / `TokenReal` / `TokenChar` / `TokenVar` / `TokenAddrOf` /
  `TokenMember` / `TokenDeref` / `TokenDerefExpr` / `TokenSubscript` /
  `TokenSubscriptExpr` / `TokenVaArg`) routes its final operand through
  `emit_ir_value`, so shape normalization and type coercion happen in
  one place instead of being re-derived at each compile site.
  `IRBuilder::coerce` grew function-ref ↔ pointer and int ↔ real paths.

- **Stage 2 binary-op collapse.** Seven helpers (`emit_compare` +
  `CmpKind`, `emit_plain_binop3`, `emit_plain_divmod`,
  `emit_plain_bitop2`, `emit_compound_binop3`, `emit_compound_bitop2`,
  `emit_compound_divmod`) absorb every plain-numeric fast path.
  `GeneralBinopCascade` + `begin_general_binop` / `finish_general_binop`
  absorb the general-fallback cascade in all eleven binary-op tokens.
  `emit_pointer_arith_scale` extracts the `p ± n*sizeof(*p)` logic
  from `TokenAdd` / `TokenSub`. `emit_inc_dec` collapses `TokenInc` /
  `TokenDec` into a single `SafeUnaryStep`-keyed lowering.

- **Stage 3 call-path normalization.** `bind_call_return` grew a
  `narrow_int_ret` flag and now unifies the fptr / dlcall / variadic
  dlsym return-binding paths — Mem-destination call returns work
  uniformly. Fn-pointer call dispatch cleaned up (UB
  `reinterpret_cast<Operand*>(&gp)` removed; stack-backed fn-ptr
  variables now load through a Gp so the downstream invoke can't see
  a Mem). Three new var-move helpers (`load_var_to_gp`,
  `lea_var_to_gp`, `store_gp_to_var`) folded the lambda-capture
  pack / reload and multi-return integer-unpack loops onto one
  shape-dispatch site.

- **Bugs fixed as side effects.** (1) `TokenNeg`'s dead-code
  `is_plain_numeric_expr(left)` branch (unreachable since `left` is
  always NULL for unary minus) was silently calling `safeshl` instead
  of `safeneg` — replaced with a real unary-right IR-normalized fast
  path. (2) `TokenCallFunc` dlcall return-binding ignored Mem
  destinations; now honors them. (3) Stack-backed fn-pointer variables
  would have crashed the downstream invoke on `as<Gp>()`; now load to
  a Gp first.

- **Five more IR unit tests** locking in `IRBuilder::coerce` behavior
  for int↔real conversions (cvtsi2sd/ss, cvttsd/ss2si) and int64→int32
  narrow relabel that Stage 1 / 2 introduced.

## Test baseline

- 25 datadef + 23 IR = 48 unit doctest cases, all passing.
- 170 integration tests, all passing.
- Green after every commit in the 17-commit Stage 0→3c sequence.

## What's still pending

- `typesafe.cpp` `safe*` shrinkage — the surviving shape-dispatch in
  safeadd / safesub / etc. is mostly legitimate Xmm-vs-Gp; audit needed
  to find genuinely dead branches now that upstream normalizes.
- `TokenBSL` / `TokenBSR` stream I/O paths (`cout << x`, `cin >> y`)
  still reach asmjit directly; they weren't refactored because of the
  parser-level stream dispatch complications.
- `TokenReturn`'s multi-return write path still uses Gp/Xmm/Imm/Mem
  explicit dispatch; could route through safemov with care.
