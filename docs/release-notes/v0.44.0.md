# Release v0.44.0 — 2026-07-25

The Mach-O release: madc on Linux emits complete, ad-hoc-signed Apple
Mach-O executables for both arm64 (Apple Silicon) and x86-64 (Intel)
— MIR is the compiler, assembler, linker, and code signer; no Apple
toolchain anywhere in the product path. The first emitted binaries ran
on real Macs the same day the writer was written (identical output on
both, exit code intact, Apple Silicon's AMFI accepting the
MIR-generated signature). Ships with MIR fork release 1.0-madc.0.44.0.

- Fork: `mir-macho.c` — the Mach-O64 MH_EXECUTE writer behind the
  `MIR_object` seam: PIE images with LC_MAIN entry (no `_start` stub),
  classic dyld rebase/bind streams over the addrpool-as-GOT model (no
  stubs, no lazy binding, no indirect symbol table), nlist symtab,
  real LC_FUNCTION_STARTS, deterministic content-hash LC_UUID, and a
  linker-signed ad-hoc code signature (inline SHA-256, 4K signing
  pages) — mandatory on Apple Silicon.
- Fork: `MIR_TARGET_X86_64_MACOS` joins the target matrix; the c2mir
  predefine/typedef headers are keyed on the target (not the build
  host), so cross builds compile true darwin code from Linux.
- madc: `make -C src cross-x86-64-macos` / `cross-arm64-macos` build
  emit-only cross compilers `bin/madc-x86-64-macos` /
  `bin/madc-arm64-macos`; pure C `-o`, `.mad` `-o`, and `-c`×2 →
  madc-link all produce signed Mach-O PIEs; run lanes refuse loudly;
  runtime-needing programs fail at emit with a clear message.
- Gate B (all-Linux): llvm-18 oracle validation against
  clang+ld64.lld reference binaries — layout, dyld streams, symbols,
  disassembly, and an independent re-hash of every signature page.
  Gate B-final (owner-run): green on both an Apple Silicon and an
  Intel Mac.
- Host regression battery unchanged: fulltest 754/0/0/9, exe 738/0,
  packed 754/0/0/9.

Next: MH_OBJECT `.o` flavor; owner route decision on the larger goal
(madc-release running natively on macOS).
