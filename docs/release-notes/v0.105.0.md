# Release v0.105.0 — 2026-10-15

**The live REPL and the pack slices.** A `madc -i` session now behaves like a
buffer you keep editing: a function, a variable or a type you define again takes
effect at once, an edit to the REPL buffer reparses live, and Restart and Run All
replays the whole buffer in a fresh session. On the pack side, the forest pack
now holds every system header the platform ships and is cut into per-unit slices,
so a packed madc compiles any system-header program on a machine with no headers
on disk and a bind loads only the units a program includes. madcide 0.8.0 carries
the live reparse and Restart and Run All to its REPL pane.

## Highlights

- **Redefine a function; every call reaches the newest body.** In a `madc -i`
  session a function defined again replaces the earlier body everywhere: a later
  call, a caller compiled before the redefinition, a function pointer taken
  before it, and an inline or in-class member function (Julia's rule).
- **Redefine a variable in place.** An object defined again with the same type is
  initialized again in the same storage, so every function and every pointer
  taken earlier reads the new value; an object with a destructor — a madc `var`
  included — is destroyed first and constructed again in place.
- **Redefine a type: the name's next version.** A struct, union or class defined
  again with the same data members is the same type; defined with other members
  it becomes the name's next version — the name means the new type while the
  objects and functions made with the earlier one keep it, shown as `P#1`
  (Julia 1.12's world age), and mixing versions is a type error.
- **The REPL buffer reparses live.** An edit a colon command makes to the REPL
  buffer takes effect at once: the entries it changed are read again as
  definitions only, so functions are redefined and variables re-initialized
  while statements never run again.
- **Restart and Run All.** `%run` with the REPL buffer current — and madcide's
  Build ▸ Restart and Run All (`%runall`) — restarts the session, replays the
  whole buffer entry by entry, then runs the buffer's uncalled `main`.
- **Objects with static storage duration are destroyed at exit.** A global, an
  array global or a block-scope static has its destructor run at exit, in reverse
  order of construction and interleaved with `atexit` handlers, in the JIT and in
  native executables; a madc-built shared object unloaded before exit runs its
  destructors at the unload.
- **A packed madc compiles any system-header program with no headers on disk.**
  The forest pack holds the exact text of every header the platform's C library,
  kernel and C++ standard library install, and the release madc reads those core
  system headers from libmadc rather than /usr/include (`--no-embedded-headers`
  sends them back to disk).
- **The pack is cut into per-unit slices; a bind loads only what a program
  includes.** A bind visits and judges only the slices of the units a program's
  include closure reaches and builds a derived type on first use, so a `<vector>`
  bind no longer carries `<string>`'s products and the packed front-end cost of
  `<vector>` drops from 352M to 76M instructions.
- **A packed compile that binds nothing never decodes the pack.** A dialect
  compile binds no packed unit, so it no longer decodes the whole container on
  every fragment include; the dialect prelude binds directly from its own frozen
  unit, and a bare `println("hi")` falls from 86.9M to 15.1M instructions.
- **A dialect host colours what the CLI colours.** `madc::theme_styles` and
  `madc::theme_paint` expose the CLI's theme reader and painter, and the ex and
  session faces carry `shown_code`, so madcide paints `:%p` and `%type` exactly as
  `madc -i` does.
- **A new README and `SECURITY.md`.** madc presented as a self-contained C and
  C++ compiler (JIT, AOT, REPL), with timings against g++ and clang++.
- **madcide 0.8.0** (pinned to madc 0.105.0): an edit to the REPL buffer takes
  effect at once, Build ▸ Restart and Run All (`%runall`) replays the REPL
  buffer, and the REPL pane paints code through madc's own painter.
