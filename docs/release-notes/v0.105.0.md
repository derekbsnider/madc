# Release v0.105.0 — 2026-10-13

**The live REPL release.** A `madc -i` session now behaves like a buffer you
keep editing: a function, a variable or a type you define again takes effect at
once, an edit to the REPL buffer reparses live, and Restart and Run All replays
the whole buffer in a fresh session. madcide 0.8.0 carries both to its REPL
pane.

## Highlights

- **Redefine a function; every call reaches the newest body.** In a `madc -i`
  session a function defined again replaces the earlier body everywhere: a later
  call, a caller compiled before the redefinition, a function pointer taken
  before it, and an inline or in-class member function (Julia's rule). Before,
  C refused the second body and C++ / madc silently kept the first.
- **Redefine a variable.** An object defined again with the same type is
  initialized again in the same storage, so every function and every pointer
  taken earlier reads the new value; an object with a destructor — a madc `var`
  included — is destroyed first and constructed again in place. A type change,
  a `const` object and an array whose size changes are refused with a hint to
  `%run`, and keep their value.
- **Redefine a type: the name's next version.** A struct, union or class
  defined again with the same data members is the same type, and a class's
  member functions are redefined. Defined with other members, it becomes the
  name's next version: the name means the new type, while the objects and
  functions made with the earlier one keep it, shown as `P#1` (Julia 1.12's
  world age). Mixing versions is a type error, never a silent copy. In madc and
  C++ a function defined again for the new version is an overload, mangled as
  g++'s `abi_tag` would (`getx(P[abi:v2])`); in C it is refused with the `%run`
  hint.
- **The REPL buffer reparses live.** An edit a colon command makes to the REPL
  buffer takes effect at once: the entries it changed are read again as
  definitions only, so functions are redefined and variables re-initialized
  while statements never run again. An edit that gives a type a new version
  also re-reads the functions below it that name the type.
- **Restart and Run All.** `%run` with the REPL buffer current — and madcide's
  Build ▸ Restart and Run All (`%runall`) — restarts the session and replays the
  whole buffer, entry by entry, then runs the buffer's `main` when it defines
  one that no entry called (argv[0] is `[REPL]`). Two new dialect verbs,
  `madc::session_edited` and `madc::session_rebuild`, give a host the live
  reparse and the rebuild.
- **Objects with static storage duration are destroyed at exit.** A global, an
  array global or a block-scope static now has its destructor run at exit, in
  reverse order of construction and interleaved with `atexit` handlers, in the
  JIT and in native executables; a madc-built shared object unloaded before
  exit runs its destructors at the unload. `atexit`, `at_quick_exit` and
  `pthread_atfork` link from madc's own startup members.

## Fixes

- A global declared `extern` ahead of its definition is initialized by the
  definition (`extern S s; S s(5);`); before, it was default-constructed.
- A class argument that no conversion turns into the parameter's class is a
  compile error (`no matching constructor for call to 'B(A)'`); before, the
  parameter was default-constructed and the program read garbage.
- A conversion-function template (`template <typename U> operator Val<U>()`)
  converts to the class deduced from the target ([temp.deduct.conv]); before,
  the target was default-constructed.
- `__has_trivial_destructor(var)` is false, as for `std::string` in g++ and
  clang++.

## Companion releases

- **madcide 0.8.0** (pinned to madc 0.105.0): an edit to the REPL buffer takes
  effect at once, and Build ▸ Restart and Run All (`%runall`) replays the REPL
  buffer; `%run` stays the editor's file.
