# madc v0.102.1

**Ubuntu 24.04: madc's and madcide's windows open under AppArmor.** The patch to
v0.102.0 is packaging and release tooling: the `.deb` built on Ubuntu 24.04 and
later carries an AppArmor profile so madc's and madcide's windows get the user
namespaces WebKit's sandbox needs, the release's `SHA256SUMS` names the `.deb`
assets as GitHub stores them, and release tooling no longer stales the test
lanes. No source code changed; v0.102.0's validated battery is the release gate.

## Features

- **AppArmor profile in the Ubuntu 24.04 `.deb`.** Ubuntu 24.04 and later set
  `kernel.apparmor_restrict_unprivileged_userns=1`, denying an unprofiled
  program the user namespaces WebKit's bwrap sandbox needs, so on a native 24.04
  desktop madcide's window — and any `ui::` program run by `/usr/bin/madc` —
  died at its first rendered page with SIGTRAP, exit status 133 (LP: #2046844);
  WSL, containers and 22.04 do not restrict them. The `.deb` built on 24.04 and
  later installs `/etc/apparmor.d/madc` (profiles `madc` and `madcide`:
  unconfined plus userns, the shape of Ubuntu's own WebKit-app profiles), loaded
  by postinst. `package_install_gate.sh apparmor` proves the window stays up
  15 s with the restriction on, against a control that never renders with the
  profile unloaded; `release.yml` runs the gate on the 24.04 runner.

- **Release assets named as GitHub stores them.** GitHub writes a `~` in an
  asset name as `.`, so v0.102.0's published `SHA256SUMS` mismatched its `.deb`
  names (`sha256sum -c` failed for both debs). The release renames the debs to
  the GitHub spelling before checksumming (the package Version keeps its `~`),
  and the published v0.102.0 `SHA256SUMS` was re-uploaded with the `.` names,
  hashes verified against the downloaded debs. One `.deb` per Ubuntu release
  makes 10 assets.

- **Release tooling no longer stales the test lanes.** A packaging,
  release-archive or gate script change shares nothing with the source the test
  suite runs; `RELEASE_TOOLING` excludes that tooling from a lane's content, and
  each lane carries only the tools it itself runs.

- **Chthonia's relation corrected.** Chthonia is its own product, in its own
  repository, whose packages each carry their own madc release; nothing is
  installed from madc for it.

## Validation

No source code changed since v0.102.0, so the packaging and release-tooling
patch rides v0.102.0's validated battery — every platform lane's full suite
green on the shipped packed -O2 `madc-release`.
