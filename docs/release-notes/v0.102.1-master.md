# madc v0.102.1

**The bug-fix release for v0.102.0.** v0.102.1 began as the Ubuntu 24.04
packaging patch and grew into the bug-fix release: it carries every fix banked
since v0.102.0, not only the packaging change. madcide gains autoindent;
aarch64 and macOS executables that define variadic functions link and run;
macOS images with large zero-filled data load; aarch64 passes floating-point
aggregates the way the platform ABI requires; a Windows GUI program run with
`--tui` gets a usable console; and the `.deb` built on Ubuntu 24.04 opens its
windows under AppArmor. No language surface changed — these are correctness and
platform fixes on top of v0.102.0's features.

## Features

- **madcide autoindent.** Enter starts the new line with the current line's
  indentation, one step deeper after a block opener (`{` for C/C++/madc, `:`
  for Python):

      void f() {          // press Enter after the brace
          |               // the new line is already indented one step

  A `}` typed first on an otherwise-blank line dedents one step, as Edit ▸
  Dedent does, and a single undo takes back both the dedent and the character.
  The indent level is each buffer's own, read from its file: a tab if its
  indented lines use tabs, otherwise the number of spaces it most often steps
  by (a file with no indented line yet uses its language's default — four
  spaces for Python, two for YAML, a tab for everything else). Autoindent is on
  by default; Edit ▸ Toggle Autoindent (the `I` row of `^T` Options) turns it
  off and keeps the choice in settings.json.

- **macOS and aarch64 executables that define variadic functions link and
  run.** A madc-compiled program that defines a variadic function reaches
  libmir's `va_arg` / `va_block_arg` builtins, which were exported only on
  x86-64 ELF and PE; on aarch64 Linux such an executable failed to link, and on
  macOS (arm64 and Intel) it built and then aborted at launch with exit 134.
  Both names are now exported on ELF and Mach-O, so the native executable links
  and runs — a program using `int`, struct, long double and 160-byte by-value
  `va_arg` prints `3 6 6 6.25`, matching gcc on the Mac mini (arm64,
  macOS 14.8) and the Intel MacBook (macOS 15.7), where before both aborted.

- **macOS images with large zero-filled data load.** A native Mach-O image
  whose zero-fill `__DATA` (bss) reached past its data's file pages placed
  `__LINKEDIT` inside the bss address range, and dyld refused it ("vm range of
  segment '__DATA' overlaps segment '__LINKEDIT'") — killing an executable at
  load and failing a shared library's open (`libmadcide.dylib` on Intel macOS
  once its bss outgrew the slack). Past `__DATA` the file and the address space
  now part ways as in ld64's layout, so the extra carrier and `__LINKEDIT`
  start at `__DATA`'s memory end in the address space; the image loads, and a
  library with 64 KiB of bss builds, opens, reads and writes, matching Apple
  clang `-dynamiclib` plus a dlopen host.

- **aarch64 passes floating-point aggregates per the platform ABI.** aarch64
  now passes and returns homogeneous floating-point aggregates (a struct of 1–4
  floats, doubles or long doubles) in consecutive FP registers per AAPCS64,
  spilling in memory layout when they run out, with results in v0–v3; a
  `_Complex` argument travels whole as a two-member HFA. Before, c2m-compiled
  and natively compiled code disagreed on every such aggregate crossing between
  them — named args, varargs and returns. Validated on aarch64 Linux against
  gcc-compiled code and under qemu, where c2m and the madc-aarch64-linux AOT
  build now match the all-gcc oracle.

- **A Windows GUI program run with `--tui` gets its console.** A Windows GUI
  image (built `-mwindows`) run with `--tui` from a Command Prompt printed
  "ui: the terminal target needs a console on stdin/stdout" and refused the
  terminal UI, because the attached console's stdout and stderr were reopened
  write-only while the terminal probe needs read access. Both streams now
  reopen read/write, so a GUI program attaching its parent prompt's console
  gets a usable console and the terminal UI opens.

- **The Ubuntu 24.04 `.deb` opens its windows under AppArmor.** Ubuntu 24.04
  and later set `kernel.apparmor_restrict_unprivileged_userns=1`, denying an
  unprofiled program the user namespaces WebKit's bwrap sandbox needs, so on a
  native 24.04 desktop madcide's window — and any `ui::` program run by
  `/usr/bin/madc` — died at its first rendered page with SIGTRAP, exit status
  133 (LP: #2046844); WSL, containers and 22.04 do not restrict them. The
  `.deb` built on 24.04 and later installs `/etc/apparmor.d/madc` (profiles
  `madc` and `madcide`: unconfined plus userns, the shape of Ubuntu's own
  WebKit-app profiles), loaded by postinst. `package_install_gate.sh apparmor`
  proves the window stays up 15 s with the restriction on, against a control
  that never renders with the profile unloaded; `release.yml` runs the gate on
  the 24.04 runner.

## Fixes, internals and process

- **MIR codegen.** An inlined call's by-value-struct argument copy is released
  each execution, so a struct argument passed in a loop no longer grows the
  stack (a 20M-iteration loop over a 24-byte struct overflowed at -O1+). Four
  upstream varargs/inlining fixes from Cyan Ogilvie are adopted: counting XMM
  block arguments in `%al` on x86-64, treating the `va_*` builtins as memory
  clobbers under GVN, not folding unencodable address computations into aarch64
  FP memory operands, and comparing the inline growth limit against the grown
  size.

- **c2mir.** Under `-pedantic`, `c2m` no longer crashes on `int x = 1;` (and a
  second declarator no longer shares the first's asm node); a numeric literal's
  range check now clears and reads errno around each conversion, so a valid
  number is no longer reported out of range. An `_Alignas` on a struct or union
  member parses (C11 6.7.2.1p1), with the member offset, aggregate alignment
  and size already raised from it.

- **MIR self-hosting.** MIR compiles itself on aarch64 via the c2mir-bootstrap
  recipe (two byte-identical `.bmir` generations), with the aarch64-linux long
  double libgcc routines resolved through the new `mir-ld-helper.h`; and MIR's
  own sources no longer depend on plain char's sign — a source byte is returned
  as unsigned char and `cs_unget` drops EOF, so byte 0xFF and an unsigned-char
  target both read correctly (`check-mir-plain-char.sh` keeps it that way).

- **Packaging and release.** The published `SHA256SUMS` now names the `.deb`
  assets as GitHub stores them (a `~` becomes `.`), so `sha256sum -c` verifies;
  one `.deb` per Ubuntu release makes 10 assets. A packaging, release-archive or
  gate script change no longer stales the test lanes: `RELEASE_TOOLING` is
  excluded from a lane's content, each lane carrying only the tools it runs.
  Chthonia is its own product, in its own repository, whose packages each
  carry their own madc release — nothing is installed from madc for it.
