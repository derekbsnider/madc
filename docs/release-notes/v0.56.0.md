# Release v0.56.0 — 2026-07-28

Real C under real headers. An explicit prototype now replaces a builtin
registration **wholesale** (gcc canon), so `getenv("HOME")` compiles and binds
real libc under real `<stdlib.h>` — the private result-buffer conventions the
old half-adopt bug was accidentally keeping alive are deleted. And explicit
template arguments now reach every layer a non-deducible call crosses, so
`std::use_facet<numpunct<char>>(loc)` binds the real libstdc++ export instead
of an invented placeholder. Suites: 776 JIT / 760 EXE / 760 OBJ, zero
failures, warning ratchet at zero.

- `FuncDef::builtin_registration` — the registration loops declare the
  intent; parseFunction replaces such an entry wholesale on a source
  re-declaration. getenv/setenv/unsetenv are the real C/POSIX functions
  everywhere; `__madc_getenv` and the setenv/unsetenv wrappers are gone
  (gate: `testgetenv_realhdr`).
- The freeze/packed lanes caught what the live lane structurally cannot:
  stamping the flag at the `addFunction` mint clobbered member-template
  instantiation entries in `.tcc` body parses the live lane defers. The flag
  is caller intent, nothing else.
- `TokenCallFunc::call_returns_reference()` — ONE owner for "does this call
  yield a reference" (declared return OR substituted override), adopted at
  the reference-init parser, `is_addressable_expression`, and the CIR
  resolver. A value-returning call in a reference initializer fails loudly
  instead of silently binding `&callee`.
- The fn-template return resolver's specifier skip covers keyword tokens
  (C++ `const` no longer breaks `const _Facet&` substitution).
- Mangled-direct instantiation consumes explicit template args: concrete
  class params match self-or-base with qualified heads (`RKSt6locale`),
  and `const F&` / `const F*` returns resolve from the explicit binding.
  `use_facet` calls bind `_ZSt9use_facetINSt7__cxx118numpunctIcEEE…`
  (gate: `testusefacet_realhdr`, pinning the full 2×2).
- Open remainder: user-DEFINED facets (no exported specialization) need
  `__try_use_facet` body instantiation — KG
  `Gap{user_facet_body_instantiation}`.
