# Release v0.37.0 — 2026-07-22

The script-mode release: madc now runs PHP-style scripts. Top-level
statements no longer need a `main` — the parser synthesizes
`int main(int argc, char **argv)` around them, with command-line
arguments in scope and `return` setting the exit status. The same arc
landed C++ dynamic global initialization (non-constant file-scope
initializers now run at startup, the g++ model) and gcc-parity exit
status from the JIT, plus the startup-latency campaign's demand-driven
forest bind (packed trivial-C startup 94 → 38 ms).

Highlights:

- **Script mode (madc dialect):** statements at file scope are adopted
  in source order into a synthesized `int main(int argc, char **argv)`;
  declarations keep their normal file-scope meaning and interleave
  freely. Works identically across the JIT, `--emit=c11`, `--dump-cir`,
  and the native `-c`/`-o` artifact lanes.
- `argc`/`argv` are in scope for top-level statements
  (`puts(argv[1]);` just works); a top-level `return expr;` is the
  process exit status.
- Dynamic global initializers run first (`__madc_global_init` at main
  entry), then the script body — the C++ mental model.
- Guard rails: statements plus an explicit `main` is a hard compile
  error (both orders, each citing the other's location); a statement in
  an `#include`d file is an error; explicit `--std=c*`/`c++*` keep the
  standard "expected a declaration" error.
- **C++ dynamic global init:** `int scaled = base * 2;` and
  call-initialized globals now compile in every C++-presenting mode
  (previously a c2mir constant-expression error).
- **Exit status parity:** the JIT lane now propagates main's return
  value (`./prog; echo $?` matches gcc); the native lane always did.
- Startup latency (task #89, also in this release window): two-stage
  forest open with an early config gate, demand-built indexes, lazily
  decoded template segments, attributed admitted-set seeds — packed C
  hello 94 → 38 ms, `--std=c17` 45 → 15 ms, C++ hello unchanged.
- Five new integration tests (`testscriptmode`, `testscriptargv`,
  `testscriptreturn`, `testscriptmainconflict`, `testscriptstd`);
  fulltest and the packed suite at **734/0/0/13**, native `--exe` lane
  **720/0**.
