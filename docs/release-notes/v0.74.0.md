# Release v0.74.0 — 2026-08-09

Reference-binding correctness release. A converted argument (e.g. a
`char` buffer where a method takes `std::string&`) used to bind a
hidden temporary: the callee wrote into the temp, the caller's object
stayed untouched, and the program printed wrong output with exit 0.
madc now matches g++/clang++ ([dcl.init.ref]p5) and rejects the call at
compile time.

- Overload ranking scores a user-defined-conversion binding to a
  non-const lvalue reference as non-viable; argument lowering refuses
  with `cannot bind a non-const lvalue reference parameter to a
  converted temporary` at the call site.
- One predicate owns the rule (`FuncDef::is_nonconst_lref_param`),
  consulted by all eight ranking sites and six argument-lowering
  loops. Positive-evidence only: explicitly spelled `T&` params are
  gated; typedef'd refs (libc++'s `push_back(const_reference)`) abstain
  until FEATURE_CONST_TYPES carries alias const-ness in the type graph.
- Legal bindings are pinned green: `char*` → `const string&`
  temporaries, lvalue → `string&`, and `&&` overload sets
  (tests/testconstrefbind); the errors are gated by
  tests/testnonconstref and tests/testnonconstrefmember.
- Release flow now archives each release's `bin/madc-release` under
  `tmp/release-bins/` for cross-release timing comparisons.

Validation: JIT 1005/0 (9 skipped), EXE 982/0, OBJ 982/0, packed
1005/0, libc++ lane 1001/0 (13 skipped), unit tests all green.
