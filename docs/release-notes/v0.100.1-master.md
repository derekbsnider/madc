# madc v0.100.1

**madc now compiles every translation unit of its own backend.** This is a
bugfix release on top of v0.100.0, and its headline is a milestone rather
than a feature: the five C files that make up MIR and c2mir — 33,629 lines
of real, hostile, macro-dense systems C — all compile clean under madc.
That was the point of the CIR backend from the beginning, and it took
seven root-cause fixes in the preprocessor and parser to get there. The
same release also fixes a regression that broke every macOS SDK header,
caught by the darwin lane before it could ship.

## Features

- **madc parses and compiles MIR's own source — all five TUs.**

      bin/madc --std=c17 -D_DEFAULT_SOURCE -Ithird_party/mir \
               -Ithird_party/mir/c2mir -c -o x.o third_party/mir/c2mir/c2mir.c

  `c2mir.c` (12,041 lines), `mir-gen.c` (10,520), `mir.c` (7,474),
  `mir-debug.c` (3,456) and `mir-debug-gdb.c` (138) each produce an object
  file. Getting there meant fixing real C the compiler had never met: the
  preprocessor's "blue paint" across macro-argument pre-expansion (551
  double expansions in `c2mir.c` alone), a macro hidden while its own
  arguments were pre-expanded, a macro argument's leading newline being
  pasted by `##`, an anonymous `union` member with a cv-qualifier, and a
  cast whose dereference operand is itself a cast. Each fix carries a
  reducer checked against both gcc and clang.

  The remaining gap to *linking* a madc-built libmir is eight
  `asm()`-label alias exports: madc redirects references through the asm
  name but does not yet emit the alias symbol.

- **GNU `asm` labels are honoured on declarations**, as gcc does —
  `extern char probe asm ("mir.arg_memcpy");` really does refer to that
  symbol. c2mir parses the label and discards it, which is why this is the
  one place madc is stricter than the backend it targets, and why madc
  alone hit the name collision that fix resolves.

- **A new correctness lane that catches wrong answers, not just crashes.**
  [index-c](https://github.com/kostya/index-c) is one 16k-line C program
  running ~50 real-world tasks, each checksumming its own result against a
  known-expected value. A wrong lowering surfaces as a wrong number rather
  than a segfault — the class the output-matching suites are weakest at.
  All 50 pass, and the lane also puts a number on the optimizer gap: madc
  is *faster* than `gcc -O0` (104.0s vs 118.0s) and 1.57x slower at `-O2`
  (85.0s vs 54.2s).

## Fixes

- **A variadic tail's pieces are separate arguments for macro hiding.**
  Two invocations of one macro in different comma-separated pieces of the
  same `__VA_ARGS__`: only the first expanded. macOS `<sys/qos.h>` spells
  six enumerators exactly that way, so the literal macro name landed in
  enumerator position and *every* test reaching a real macOS SDK header
  failed. A regression against v0.100.0, caught by the darwin lane and
  classified by running the reducer against the actual v0.100.0 release
  binary rather than inferred from the diff. The darwin suite goes
  1520 → 1533 (arm64) and 1521 → 1534 (Intel).

- **A type qualifier may sit inside a type-specifier run** (C99 6.7.2p2):
  `unsigned const char` names the same type as `const unsigned char`. The
  lexer ended its specifier run at the first non-specifier word, so the
  lone `unsigned` minted as `unsigned int` and `const char` arrived as a
  second base type. `unsigned char const *` always worked, which is why the
  failure looked arbitrary.

- **`_MIR_builtin_func` adopts an existing import of the same name**
  instead of refusing it. In one translation unit `mir.arg_memcpy` is both
  an import the program spells and a helper the generator registers; a
  non-import item of that name is still a real conflict and still raises.
  Fixed in-tree at `third_party/mir`; upstream-worthy.

- **`__builtin_constant_p` is a parse-time builtin**, not a macro that
  always answered `0`.

## Infrastructure

- Two lanes that existed only inside `remote_build.sh` — the GUI stage and
  the c2mir corpora — are named lanes with ledger rows, so nothing can run
  unowned and drift unnoticed.
- Ratchets: gcc c-torture 1611 → 1612, the c2mir corpora lane 298 → 302 of
  359, the packed-header preprocessor parity baseline 158 → 146 known
  divergences from `g++ -dM`.

## Known open

- `headerless-win` carries two failures: the win64 header pack serves no
  prototype for `printf`, so an undeclared call falls back to the
  zero-parameter variadic guess. Pre-existing against the published
  v0.100.0 artifact and non-gating.
- `MIR_link` raises on an undefined *weak* import rather than resolving it
  to zero.
- The darwin `--exe` lane stays advisory until the darwin runtime dylib
  ships: `-static-libmadc` cannot cover the C++ script-lane runtime.
