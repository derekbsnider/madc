# Release v0.42.0 — 2026-07-25

The inline un-erasure release (ELF-completion S4 follow-through).
`inline` is now a real C++ specifier carrying vague linkage instead of
a lexer-erased storage hint: explicitly-`inline` user-header functions
— S4's documented loud boundary — and C++17 inline variables merge
`STB_WEAK` across translation units at native and external links.
madc-only change; ships against the unchanged MIR fork release
`1.0-madc.0.41.0`.

## Highlights

- **The `sumv` boundary is closed** — an `inline` free function defined
  in a shared user header links and runs in every native lane (madc
  link, run-direct merge, `-r`, external gcc/ld) instead of colliding
  as a duplicate strong definition.
- **C++17 inline variables** — the data symbol binds `STB_WEAK` and
  per-TU copies merge (function AND data); a dynamic initializer runs
  **exactly once** per merged image behind a linkonce once-guard
  (`__madc_ivg_<sym>`), the g++ guarded COMDAT-init model.
- **One keyword, every position** — `inline` joins the version-gated
  C++ keyword registry (the constexpr precedent); `__inline__` /
  `__inline` map to it; it is consumed leading, mid-declaration-seq,
  and in class bodies; `inline namespace` moves onto the keyword path
  (the lexer carve-out is deleted).
- **Correct linkage edges** — `static inline` stays internal (never
  weak, gcc parity); out-of-class `inline C::m()` definitions get
  vague linkage; C modes keep today's erasure (C99 inline semantics
  are unchanged, nothing breaks).
- **`--emit=c11`** renders the variable marker as portable
  `__attribute__((weak))`; two emitted-C TUs gcc-compile warning-free,
  link, dedupe, and run.
- **Suite state** — fulltest + packed arbiter 754/0/0/9 (+1 new test);
  `--exe` and `--obj` lanes 738/0 each; 20/20 container gates including
  the external gcc/ld and g++ source oracles; unit suite grew the
  two-TU weak-merge + init-once case.
