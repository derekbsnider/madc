# Release v0.48.0 — 2026-07-25

Forest carriers S3: the frozen forest becomes **discoverable**. madc now
walks an ordered carrier probe chain instead of knowing exactly one
place to look, the build grows a `--with-forest=` axis so the packaged
shapes (embedded binary vs sidecar file) are configuration rather than
destiny, and the failure policy is explicit — the packaged CLI falls
back loudly, embedding hosts can demand strictness, and the dev tree
stays silent. Green across the full shape × platform matrix: the Linux
test arbiter runs through BOTH carriers at identical counts, and all
legs pass on Apple hardware on both architectures.

Highlights:

- **Carrier discovery chain** (first usable container wins): 1. the
  binary's own image (ELF trailer / Mach-O `__MADC,__forest` section),
  2. *(reserved: library image via `dladdr` — S4)*, 3. `<exe>.forest`
  sidecar beside the binary, 4. the `$MADC_FOREST` path, 5. *(reserved:
  `madc.ini` / baked default — S6)*. Every arm validates identically
  (footer, context hash, format version, producer-config gate).
- **`--with-forest=embedded|sidecar|none`** configure axis (default
  embedded): what the product build ships and expects — never a
  restriction on discovery. Sidecar shape: `forest_pack.sh --sidecar`
  writes `bin/madc-release.forest`; hosted darwin keeps the
  cross-freeze and ships `<bin>.forest` instead of `-sectcreate`;
  `make install` places `bin/madc.forest`.
- **Failure policy** in the `RegistrationPolicy` sandbox-knob family:
  `forest_missing_policy` — `silent_fallback` (dev default),
  `loud_fallback` (one stderr notice; baked into product builds via
  `MADC_FOREST_EXPECT_*`), `strict_require` (hard error for embedding
  hosts that must never silently degrade) — plus
  `enable_external_forest` so sandboxed hosts can forbid external
  redirection of frozen-state loading.
- **Multi-dialect contract preserved**: a container found but frozen
  under a different std/`-D` config is never a loud notice (the packed
  CLI compiling C against its C++-parsed corpus is the everyday case);
  strict mode still errors, naming the mismatch.
- **Explicit `--forest-bind=` that fails to open is a loud
  fall-through** — never silently ignored.
- **New permanent gate** `forest_sidecar_gate.sh` in fulltest (external
  arms bind with engagement evidence + byte parity vs live parse, arm
  order pinned, loud failure surfaces) plus policy unit tests; the S2
  emitpack gate is now rev-skew-immune (per-arch self-frozen
  containers).
- **Evidence**: Linux fulltest 756/0/0/9, exe 740/0, arbiter through
  embedded AND sidecar carriers both 756/0/0/9; Apple hardware 7/7
  legs per arch (A64 native + X64-Rosetta) — embedded regression,
  sidecar bind + parity, loud-on-missing, quiet-on-mismatch.

The MIR fork is unchanged since v0.47.0 (`1.0-madc.0.47.0` remains the
pinned release; no new fork tag).
