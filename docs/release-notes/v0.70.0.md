# Release v0.70.0 — 2026-08-08

The data-channel streaming and process-flow core lands (Track 5A):
madc's data substrate gains dependency-free typed streaming over
memory, files, FIFOs, TCP/UDP/UDS sockets, and child processes, behind
ABI-compatible extension seams that leave every existing Cursor,
DataDriver, and SourceAdapter consumer untouched. The madcdis/madcdat
boundary is now dependency-based: madcdis owns all core/OS
functionality, madcdat owns external-library providers.

Highlights:

- **Typed streaming end-to-end**: lazy `Sink`/`Flow` adapters,
  capability-probed streaming extensions (`StreamingSourceAdapter`,
  `StreamingDataDriver`, `ErrorAwareCursor`) with automatic fallback
  to the legacy vector APIs, and native incremental DSV scans.
- **A dependency-free `DataChannel` framework**: memory, file, FIFO,
  and TCP/UDP/UDS channels behind one scheme registry, a
  `std::iostream` bridge, SIGPIPE-safe writes through one owner,
  datagram truncation refused, real byte-stream half-close.
- **`Process` endpoints**: explicit argv/env/cwd (no shell), three
  independent standard-stream channels, exec-errno reporting over a
  cloexec self-pipe, guaranteed reaping, and bounded concurrent
  pumping via `pump_process`.
- **Storage core relocated** madcdat → madcdis as a verified faithful
  move; the DSV/FLR/VLR and storage-contract suites now pass in the
  `--enable-madcdat=no` core build too.
- **Hardened in review before merge**: atomic close-on-exec at fd
  creation (with the portable darwin fallback), one channel-pump
  owner, documented channel/pump thread contracts, and two new
  fulltest gates holding the SIGPIPE and cloexec policies.
- Battery: fulltest **999/0**, libc++ lane **995/0**, EXE/OBJ
  **978/0**, packed release suite **999/0**.
