# Release v0.81.0 — 2026-08-16

The Windows release lane merges after its full-suite validation on genuine
Windows, and the headerless lanes turn "madc ships its own standard headers"
from a claim into something a test run can falsify. Driving those lanes to zero
exposed a language gap nobody had looked for: madc had no C++
list-initialization at all, which meant `std::vector<int> v{1,2,3}` compiled as
`std::vector<int> v(1,2,3)` and the copy form silently produced a one-element
vector.

- **C++ list-initialization lands.** A braced list on a class type was lowered
  as a parenthesised constructor-argument list, so the first element became the
  size and the third was handed to `allocator<int>`. `= {1,2,3}` threaded only
  the first element, selecting `vector(size_type)` with `n == 1` — clean
  through `--emit=c11`, and silently wrong. Direct- and copy-list-init,
  non-`int` element types, `std::initializer_list` as the declared type, and
  user initializer-list constructors now match g++ and clang++.
- **Three defects that shipped in v0.80.0 are fixed.** `std::vector<int> e{}`
  crashed — `T x{}` is spelled internally as `x = x`, so the copy constructor
  read its own uninitialized storage. Declarations before a switch's first
  `case` label were rejected when they led with a qualifier or tag keyword. And
  a struct member typed with a class-qualified nested type
  (`ios_base::fmtflags _M_mask;`) was rejected, which stopped `<iomanip>` on
  its first line of content, taking `std::get_time`, `setw` and `setprecision`
  with it.
- **The headerless lanes run with the battery.** They are the only lanes that
  can observe an artifact failing to serve a standard header from its own
  frozen corpus — every other lane has the headers on disk, or reaches them
  through Wine's `Z:`. Linux 1027/0/0TO/35skip, Win64 1010/0/0TO/52skip.
- **The Windows artifact's compiler-less promise has in-vivo evidence.** All
  seven `win_battery` legs pass on genuine Windows, including the leg that
  compiles a C translation unit on a host with no toolchain installed, and the
  negative-control leg that must still see failures.
- **A lane that tested nothing can no longer report success.** The `headerless-win`
  stage passed its profile as a positional argument, which `run_tests.sh` reads
  as a test filter: it ran the wrong profile against 0 of 1063 tests and exited
  0. Fixed at both layers, with a vacuity guard and a negative control.
- **Packed-lane startup is measured, and binding beats parsing.** Serving the
  frozen corpus costs 138ms against 196ms for a live parse of the same headers
  by the same binary. An earlier +50ms regression claim in this cycle was a
  measurement artifact and is retracted in the changelog; the real figure is
  +22ms against v0.80.0, about half of it the larger image rather than the
  larger corpus.
