# Release v0.72.0 — 2026-08-08

The data-channel substrate reaches the language. `madc::channel` — one
URI-addressed byte channel with line helpers — lands in `<ns_madc>`,
resolved mangled-direct to the same class embedders get from
`include/madcdis/channel.h`. A script opens `exec://sort` or
`tcp://host:port` in a few lines; the suite gains its first
script-level tcp/exec coverage, httpget included.

- **`madc::channel`** — `readline`/`readall`/`write`/`close_write` over
  any registered scheme (`file`, `pipe`, `tcp`, `udp`, `uds`, `exec`);
  CRLF-clean line reads, latched `ok()`/`last_error()`, buffered bytes
  served to `read()` before the wire. Docs:
  `docs/language/channel.md`.
- **`exec://` is a first-class channel scheme** — write → child stdin,
  read → child stdout; URI argv splits on single spaces (NOT a shell);
  stderr is inherited, never a silently-blocking pipe.
- **`Process` gains spawn-PATH resolution** (posix_spawnp shape) and
  `ProcessOptions.inherit_stderr`; `pump_process` skips its stderr leg
  when there is no stderr pipe.
- **Three hermetic suite legs** — `testexecchannel.mad`,
  `testtcpchannel.mad`, `testhttpget.mad` (loopback listeners built
  with raw libc calls in the same script; no external network). Green
  in JIT, EXE, OBJ, and the libc++ lane.
- **Flavor marshalling grows its method half** (task #69) —
  host-flavor twin minting for class METHODS, so madc-owned classes
  with `string&` parameters work under `-stdlib=libc++`.
- **One runtime-error composition owner** — dupaudit find consolidated
  and gated (`check-one-error-composer.sh`).

Battery: 1002/0 JIT (9 skips), 981/0 EXE, 981/0 OBJ, 998/0 libc++ JIT
(13 skips), 1002/0 packed. MIR fork unchanged (`1.0-madc.0.68.0`).
