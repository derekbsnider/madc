# madc v0.106.1

**A patch release for Windows.** It fixes two regressions in v0.106.0, both on
Windows. madcide's Run printed a pack-writer report on stderr for every
program that included a system header, and the Windows release build stopped
in a fresh tree. What madc compiles, and how fast, is unchanged from
v0.106.0. madcide releases alongside as **madcide 0.9.1** and Chthonia as
**Chthonia 0.3.1**, both carrying madc 0.106.1.

## Features

- No new features. This release carries v0.106.0's features unchanged; see
  the [v0.106.0 notes](v0.106.0-master.md).

## Fixes

- **A library Run on Windows is quiet again.** On Windows, `madc::parse_run`
  (madcide's Run) freezes the live parse to a temporary snapshot before it
  runs the program. For a program that includes a system header, v0.106.0
  printed `madc: pack spelled names: frozen unit N (...) carries no source
  text — the table is left out` on stderr on every Run. madcide's own
  Windows test suite failed on it. The pack writer's informational reports
  now print only when a freeze asks for progress, and a Run's freeze does
  not ask.
- **`make -C src release-windows` works in a fresh tree.** The hosted
  Windows build reads the dialect's and the modules' generated tables from
  the host's dev madc. The target now builds that madc first. Before, a tree
  with no `bin/madc` stopped with `No rule to make target '../bin/madc'`.
  The v0.106.0 Windows zip had been rebuilt from the fix branch.

## Process

- A patch release (x.y.Z, Z > 0) is measured and may lower no C23 / C++20
  conformance count, but needs no rise and no consolidated duplicate family.
  `check-release-conformance.sh` and `check-release-consolidation.sh` read
  the version's last component, and each carries a patch control.
