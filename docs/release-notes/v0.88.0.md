# Release v0.88.0 — 2026-08-19

`cout << value` streams exactly as the contained type would — the owner
ruling implemented literally: each kind forwards to the real ostream
inserter, so a value holding integer 10 streams like `int i = 10; cout << i`,
and stream state (`std::hex`, `boolalpha`) applies the way it does to the
plain type.

- One `madc::operator<<(std::ostream&, const value&)`, per-kind runtime
  dispatch; byte-identical to the plain-type twin program under g++ AND
  clang++ -O0 on every shared line, chaining included.
- null streams nothing; array/object/instance follow C++'s own convention
  (std::vector has no `operator<<`) as a stderr notice with nothing streamed
  and the stream surviving — one symbol serves C++ hosts and scripts, and no
  C++ exception may cross into JIT frames.
- Resolution: the W2 mangled-direct lane captures template operators only
  (measured), so a new type-predicate-gated carrier arm in
  `lower_free_operator_to_call` routes an intrinsic-carrier rhs to the
  concrete registered operator set. User-class arbitration untouched.
- Two pre-existing gaps found and recorded with reducers: `value(N)`
  functional-cast temporaries (garbage-kind temp — priority residue) and
  parametrized manipulator objects (`setprecision`, fails with plain doubles).
- Owner law recorded: php:: functions mirror the original PHP functions;
  invented madc-isms are drift. Next: the `php::array_push` overload set.
- Validated: fulltest 1091/0/0TO/9skip, EXE 1051/0, OBJ 1051/0, packed
  1091/0, headerless 1065/0/35skip, census 1100 tests / 0 warnings.
