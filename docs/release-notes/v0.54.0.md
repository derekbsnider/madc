# Release v0.54.0 — 2026-07-27

Six C++ correctness fixes, four of them silent wrong answers. All of them came
out of following a single reducer down: `(int)N::f(x)` compiled, exited 0, and
evaluated to `x`. Under that sat a class-qualified static call that named the
wrong thing, and under *that*, a static data member that read as `0` from
inside its own class body. The release also carries the `-stdlib=` standard-
library flavor selector and the duplication-campaign work that closed the
delimiter-tracker family.

## Highlights

- **A qualified name is only the HEAD of a postfix-expression.** `parsePostfixChain`
  resolved `N::f` and returned it bare instead of continuing the chain as its own
  unqualified tail does, so every `(`, `[`, `.` and `->` after a qualified name in
  an operand position was dropped and re-read by the caller as a fresh expression.
  `(int)N::f(x)` silently became `(int)(x)`; `(int)N::arr[1]` sent the orphaned `[`
  to the *lambda-introducer* dispatch and reported `Expecting ] in lambda expression`.

- **Class-qualified static member functions in operand position.** `(int)S::f(4)`
  reported `undeclared identifier 'S'` — the shape every string header is built
  from (`(size_t)char_traits<char>::length(p)`). The operand path carried a narrow
  copy of the class-qualifier rule; it now uses the shared resolver four other
  callers already share.

- **A static data member's declaration introduces its storage.** Reading
  `static int n;` from inside its own class body gave `0` where g++ gives `42`,
  silently; writing it reported `lvalue required`. g++ creates the decl while
  parsing the class body and lets the definition complete *that* decl
  (`finish_static_data_member_decl`); madc's equivalent of `DECL_IN_AGGR_P` turned
  out to be `vfEXTERN`, whose completion `addVariable` already implemented.

- **A nested type is a member of its enclosing scope, `struct` included.** A
  nested *struct* never registered the scope entry a nested *class* did, and a
  `struct` was never a `::` scope at all. Fixed on the principle the promotion
  site already stated: the keyword does not decide struct-vs-class, the contents
  do — a nested type now earns class-hood alongside an object member and an NSDMI.

- **Immediately-invoked lambdas, aggregate member init, base-member lifetime** —
  five broken IIFE forms (two silent), `Foo() : p{1,2}` leaving a member
  uninitialised, and base-subobject members constructed and destroyed twice.

- **`-stdlib=` selects a standard-library flavor.** A search list is a property of
  the library, not an ordering preference, so the generated table carries one list
  *per flavor* and `-stdlib=` replaces the search list rather than reordering it —
  clang's model. Which flavors exist is discovered from the build host, never listed.

- **One delimiter tracker.** The duplication campaign closed the angle-bracket
  family: 27 hand-rolled token scanners and 19 char-level ones consolidated onto
  `DelimDepth` / `SpellingDelimDepth`, with a ratchet gate in `fulltest` — and the
  gate's own marker was found to be matching a *spelling* rather than the concept,
  reporting green over eleven live scanners.

- **The Top 5 rules are now gated**, not restated: `remote_build.sh` mechanically
  refuses a concurrent container job, and `check-rule-trailers.sh` requires every
  C/C++ commit to show its `Hypothesis` / `Layer` / `Searched` / `Oracle` work.

## Known limits shipped deliberately

- A static data member of a **system-header** class still folds to a constant,
  because madc sets `storage_alias_name` for namespace-scope variables but not for
  class statics, so there is no Itanium symbol for a reference to resolve against.
  The guard that skips those is a **placeholder**, labelled as such in the code —
  `itanium_mangle_nested_var` already takes an arbitrary qualifier chain, so the
  alias is within reach of existing machinery.
- Two different scopes each declaring a `struct Inner` still collide; a nested tag
  in a struct body registers under its bare name at file scope.
