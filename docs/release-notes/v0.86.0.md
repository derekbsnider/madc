# Release v0.86.0 — 2026-08-19

The compiler now knows the C library's signatures. Three arcs land, each closing
a measured silent wrong answer: an undeclared libc call used to return garbage
read from the wrong register or the wrong width; `.count()`/`.size()` on the
value carrier answered the range-for bound's question instead of the user's; and
range-for could not take an `auto` element although everything downstream of the
type already worked.

- **Undeclared libc calls, RETURN types:** `strcmp("abc","abd") < 0` evaluated
  FALSE (an `int` −1 read out of all of rax) and `floor(2.7)` returned 1.0 (a
  double read out of rax, not xmm0) — legal C89, exit 0, wrong answers. The
  fallback default is now C's own `int`, with every non-int return in one table
  (`include/libc_signatures.h`, gcc's builtins.def model) that the lexer's
  `__builtin_` alias map and the parser expand from the same lists.
- **Undeclared libc calls, ARGUMENT types:** `floorf(3.9f)` returned 2.000 and
  `fmodf(7,4)` returned −nan — float promotion through the variadic convention.
  The table carries the nine argument shapes of the C99 math families, resolved
  by one suffix-rule owner; all nine shapes × three suffixes are byte-identical
  to gcc, headerless.
- **Two deliberate divergences from gcc, documented:** madc prints the CORRECT
  `atof`/`atoll` values where gcc itself (no entry in its builtin table) emits
  UB garbage.
- **`.count()`/`.size()` on the value carrier:** containers count elements, text
  kinds count length, null is an empty container, and a non-countable kind
  raises a real madc exception (`catch (const char *)`) — never a silent 0.
  The range-for bound (`madarray_size`) is untouched and pinned by test.
- **Range-for takes an `auto` element:** `for (auto &kv : m)` over `std::map`,
  `for (auto x : v)` over `std::vector`, raw arrays, and the madc array
  (deduces `string`, the #91 subscript ruling) — deduced at parse time through
  the same shared recognizers the loop lowering and the dumper use.
- **Two shadowing fixes** fell out of `[stmt.ranged]`: the parser now binds
  `for (auto x : x)`'s range to the OUTER array, and the raw-array lowering
  captures the range into a unique temp before the element declaration (a
  pointer-element shadow used to compile and read garbage).
- **New gates:** `scripts/check-libc-alias-signatures.sh` (every alias target
  must have a signature entry, negative-controlled) in fulltest;
  `tests/testlibcnoheader.mad`, `tests/testlibcnoheaderargs.mad`,
  `tests/testvaluecount.mad`, `tests/testforeachauto.mad`,
  `tests/testforeachautoarray.mad`.
- **Validated:** fulltest 1089/0/0TO/9skip, EXE 1049/0, OBJ 1049/0, packed
  1089/0, headerless 1063/0/35skip, census 1098 tests / 0 warnings.
