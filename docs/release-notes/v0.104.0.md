# Release v0.104.0 — 2026-10-12

**The madcide split release.** madc's interactive mode takes the ed/ex editing
core — a colon mode, a command registry modules and hosts extend, and
host-facing language services — and madc gains a Language Server (`--lsp`) and a
Model Context Protocol server (`--mcp`) with a project memory and an
external-task client. madcide moves to its own repository and releases on its
own as **madcide 0.7.0**, its first standalone release, built on and pinned to
madc 0.104.0, so madc's packages no longer carry it. Chthonia 0.1.0 builds on
madcide 0.7.0 and madc 0.104.0.

## Highlights

- **madcide moves to its own repository.** madcide — the IDE and the editor core
  it builds on — now lives in its own repository and releases on its own as
  madcide 0.7.0, its first standalone release, built on and pinned to madc
  0.104.0; madc's packages no longer carry madcide. The moved paths, gates and
  packaging stanzas leave madc, and the coverage that only madcide exercised
  keeps an engine twin here.
- **madc's interactive mode gains colon mode and a command registry.** An
  entry's first non-blank character is its mode — `%` / `.` for the REPL's
  commands, `?` for a query, `:` for ed/ex/vim colon mode over `madc::ex_session`
  — and one command registry, which modules and hosts extend, drives both REPL
  modes, `%help` and completion.
- **New REPL commands.** `madc -i` answers `%std` and `%reset`, `%history`,
  `%check`, `%build` / `%run` on the current buffer, `%args`, and `%project`
  (open, add, del, check, build, run and close the session's project), with the
  project manifest gaining a C++ writer beside its reader.
- **Coloured prompts and diagnostics.** `madc -i` colours each entry as it is
  typed, the code it shows (`%type`, `%pinfo`, `?name`) and the source line it
  echoes under a diagnostic, in the theme's colours — and carries SGR colour only
  where it reaches a terminal, matching gcc's `-fdiagnostics-color=auto`.
- **`madc --lsp` — a Language Server.** `madc --lsp` runs a Language Server
  Protocol server on stdin/stdout, answering diagnostics, document symbols,
  definition, references, hover and semantic tokens from the client's live text;
  `workspace/executeCommand` runs the REPL registry in a crash-isolated backend
  session.
- **`madc --mcp` — a Model Context Protocol server with a project memory.**
  `madc --mcp` runs an MCP server over a file or a `--project`, serving a tiered
  tool registry: 16 code-graph reads and three edits over the served documents, a
  project memory (an event stream bound to a `<base>.events` file beside the
  manifest), the served file's version history from the madcgit module, and a
  client whose `nexus.sources` / `nexus.sync` pull an external MCP system's tasks.
- **`madc::lang` — one set of language services.** A new C++ owner answers a
  document's language-service questions — diagnostics, outline, enclosing,
  definition, references, hover, spans — in one place, so the LSP, the MCP tools
  and an editor read ONE set of answers over one parse handle, with a `madc::doc_*`
  dialect face giving the same answers as rows.
- **One regex engine (PCRE2).** `madc::regex_match` / `regex_search` /
  `regex_replace` and the regex-aware `perl::grep` / `perl::split` now share one
  PCRE2 engine — the engine behind PHP's `preg_*` — so a pattern means the same
  thing on every platform; an invalid pattern is refused on stderr instead of a
  silent substring or literal-delimiter fallback.
- **A source's standard follows its extension.** A source compiled without
  `--std` now takes the standard its extension names, as `gcc` / `g++` do — a
  `.c` file as `gnu17`, a `.cpp` file as `gnu++17`, a `.mad` file as the madc
  dialect — with one owner deciding it for the CLI, a `--project` TU and the
  editor's parse alike; madc.ini gains a `modules` key, as php.ini loads
  extensions.
- **The data substrate gains a document component.** A text carries a monotonic
  version, and a document adds path, kind, read-only, a derived `modified`,
  anchors that follow edits, a checkpoint and a parse-handle slot, publishing one
  byte-precise edit notification per mutation whose change kind is an enum code.
- **A reproducible forest pack.** The pack emits unit payloads in canonical unit
  order, so two freezes of one corpus agree and the release pack is reproducible;
  the one pack profile serves the C++ modes it shares with madc (`gnu++17`,
  `c++17`); and a skipped directive-only `#ifndef` arm replays at bind.
