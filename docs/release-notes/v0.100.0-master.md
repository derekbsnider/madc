# madc v0.100.0

**The editor became a session, the IR became a graph, and C++ conformance
became a number.** v0.99.2 shipped madcide as a desktop application. This
release turns it into a *session* that many clients attach to — a second
window is a second client on the same document, with its own caret — over an
`api` transport, a headless `--serve`, a WebSocket window, an MCP seat, an LSP
face and a VS Code extension. Behind it, the **Nexus** makes madc's live IR a
node-addressed graph an agent queries and edits through validated verbs
instead of text patches. Alongside that, every C++ symbol madc defines now
emits its real Itanium mangled name — a madc object file links against g++-
and clang-built code — and C++ conformance stopped being an assertion: the
measurement was built against gcc's own testsuite, published, and driven from
60% to **75.1%**. 558 commits since v0.99.2, 205 new integration tests (the
Linux suite 1335 → 1540), and the whole of it ships in the attached packages
for Linux (`.deb` / `.rpm` / relocatable tarball), Windows x86-64 (zip) and
macOS (Apple Silicon + Intel tarballs).

## Features

- **A window is a client: `madcide file.mad --serve 127.0.0.1:7777`.** One
  cooperative loop serves N clients over the same document. Open a second
  window and it is a second seat, not a second copy — each with its own
  caret, each seeing the others' **presence carets** shift as anyone types,
  through one anchor registry, rendered identically in the terminal and in
  the web face. `--serve` alone gives you the session with no display at all.
- **Views: the same document as source, MC11, C11 or C++ — side by side.**
  A View re-represents the buffer *in place*, so source on the left and the
  MC11 IR on the right is a split, not an export. The emitter records a
  `{byte, source-line}` row per statement, so putting the caret on a line in
  one View moves the counterpart caret in the other. The editor region is a
  real split tree, tool panes are chrome slots, and layouts persist beside
  the project manifest.
- **Every change is an event, and you can replay to any point.** An
  append-only journal (`.prj.events`) whose buffer text *is* both the
  persisted form and the wire form, with checkpointing, compaction, and an
  `event:N` View that is the document's own history — open `event:120` to see
  the file as it stood 120 edits ago.
- **One process, several faces.** An `api` transport with permission tiers, an
  RFC6455 `ws` window on the same port, an **MCP seat** so an agent joins the
  session as a client, an **LSP face** for editors that speak it, a **VS Code
  extension**, an attach relay, and session discovery so a client can find a
  running madcide instead of being told its port.
- **The Nexus: the live IR as a graph an agent can edit (L1–L4e).** Graph
  verbs address nodes in the **running compiler's** IR — not a re-parse, not a
  copy — with node editing through validated verbs rather than text patches,
  PAST verbs over git history, a propose tier for changes that need review,
  intent records, asset layers and a test-runner seat. This is what makes the
  compiler's own representation addressable by something other than the
  compiler.
- **Itanium ABI compatibility: madc objects link with g++ and clang.** Every
  C++ symbol madc defines emits its real mangled name, so
  `madc -c lib.mad -o lib.o && g++ main.cpp lib.o` links — and free functions
  overload by parameter type the way C++ says they do. By-value class
  parameters and returns follow the Itanium calling convention; `extern "C"`
  opts a symbol back out to its bare name.
- **More of C++ actually works.** Expression SFINAE; pointers to members
  (types *and* values, `&C::m` through `obj.*pm`); real lambda capture lists,
  including `mutable` state persisting across calls; inheriting constructors
  (`using Base::Base;`); references binding prvalues with the temporary's
  destructor firing at the right time; `thread_local`; and the long tail of
  declarator forms that fell out of consolidating fourteen hand-rolled
  declarator readers into one owner.
- **Conformance you can check rather than take on faith.** Measured against
  corpora madc does not own — gcc's own testsuite and the third-party
  c-testsuite — and published in
  [`docs/conformance-coverage.md`](https://github.com/derekbsnider/madc/blob/v0.100.0/docs/conformance-coverage.md): **C at 99.2%**
  of the in-scope gcc c-torture set under `--std=c17` and **220/220** on
  c-testsuite; **C++98 80.0%**, **C++11 75.1%** (1464 / 1950, up from 1169 =
  60% when the lane was built four days earlier), with C++14, C++17 and C++20
  alongside. The document states what "in scope" excludes, so the figures can
  be argued with.
- **The transports work on Windows.** The async I/O reactor gained a native
  Windows backend (WSAPoll), which lifted 15 Windows skips — the session, the
  `ws` window and the attach relay are not Unix-only features.
- **`madcide file.mad -c "<command> [arg]"`** — the `ui::NONE` client: drive
  an edit from a script with no display, using the same command vocabulary
  the keys and menus use.
- **`:=` short declarations follow Go/C++ block scoping**, so a `:=` inside a
  block declares in that block and does not leak to the enclosing one.

## Fixes, internals and process

- **Three standard-C regressions found and fixed.** Measuring coverage for
  the documentation turned up gcc c-torture at 1587/1624 against 1614 six
  weeks earlier: a `static` prototype + definition read as a signature clash,
  an unprototyped declaration compared as a prototype (C17 6.7.6.3p14), and a
  compiler SIGSEGV on a cast through a `const`-qualified struct pointer. All
  three are fixed with reducers in `tests/`; torture reads **1611/1624 with
  zero regressions** against the v0.99.2 binary.
- **Suites are now tiered by time to run.** That drift lasted five weeks
  because c-torture was a 25-second run with no lane script and no ledger row
  — nothing owned it. `scripts/fast_lanes.sh` now runs c-testsuite, c-torture
  and the C++11 ratchet in under two minutes after every commit, and the
  ledger has a `commit` tier that blocks commits, merges and releases alike.
  The Xvfb `gui` stage was found in the same unowned state and given a row.
- **libgit2 left the distribution.** It is no longer a vendored subtree but
  the `madcgit` module — a dependency bound lazily, not something madc ships
  — and the module reaches the Windows and macOS cross targets.
- **A tagged enum's enumerator now has its enumeration type**, rather than
  decaying to `int`, which fixes overload selection and `format` output for
  enumerators.
- Empty static-assertion diagnostics (`static_assert(false);`), reference
  variables binding temporaries with correct lifetime, the frozen-header pack
  freezes reaching library bodies, indented and coloured emitted-code Views,
  action codes on every UI event, and the command vocabulary, state
  discriminators, UI levels and file kinds all converted from strings to
  enums.
- **A self-hosting harness** reports how much of madc's own source madc
  parses, per translation unit — turning "can it compile itself?" into a
  number that moves.

## Validation

Every platform lane ran its full suite green on one commit before this tag:
the Linux battery (JIT 1540/0, exe/obj 1444/0, packed 1540/0, headerless
1506/0, doctest 186/186), the libc++ flavor lane (1533/0, exe/obj 1437/0),
genuine Windows 11 and Wine (1480/0 each), the macOS suite on both mac runner
architectures (arm64 1520/0, Intel 1521/0), c-testsuite 220/220, gcc c-torture
1611/1624, the C++11 ratchet 1464/1950, and the Xvfb GUI stage 19/19 across
JIT, exe and obj.
