# Release v0.30.0 — 2026-06-22

This release clears the **set wall**: real-libstdc++ `std::set` and `std::map`
(including `std::map<std::string,std::string>`) now compile and run on madc's
default C++17 real-header path, with all related canaries green. It also lands
real 16-byte `__int128` end-to-end (the P0 wide-integer track) and records the
measurement-gated plan for the embedded pre-parsed-AST header forest — the next
performance track.

## Highlights

- **Set wall cleared** — a stack of eight root-cause bugs blocking real libstdc++
  ordered containers is fully resolved. `std::set<int>`/`<string>` and
  `std::map<K,V>` run on the default real-header path.
- **Final bug (7b):** a non-type template argument (`std::get<0>`'s `0`) was
  binding to the *type* parameter of the by-type `std::get` overload, naming the
  return type `"0"` and breaking `std::get` reference-binding in the piecewise
  `std::pair` constructor of `map<K,std::string>::operator[]`. Fixed at the deepest
  layer ( `[temp.arg.nontype]` substitution failure → candidate removed), matching
  clang/gcc.
- **fulltest: 669 passed, 0 failed, 0 timed out, 18 skipped.** gcc.c-torture
  failset byte-identical to the 51-name baseline; zero regressions.
- **Real `__int128` / `unsigned __int128`** end-to-end (16-byte SysV type), enabled
  by the MIR fork's scalar-int128 raise (`MIR_COMMIT` pinned); overflow builtins
  pass through at full width.
- **Drift-gate refinement:** the `call-emit-symbol` gate gained an audited
  `// allowed-exception: <reason>` per-line opt-out — `make fulltest` exits 0 with
  the gate still strict.
- **Embedded header forest plan:** measured baseline (`--show-stats`) shows parse is
  ~78% of compile wall and ~1.9 s of decl-parse is fixed header re-parse tax paid
  every compile — the prize a save-state-after-parse AST forest amortizes to a load.
