# Release v0.60.0 — 2026-07-29

std::is_destructible and is_trivially_destructible now answer correctly under
BOTH stdlib flavors and in every lane — live parse, forest-bound, and the
packed binary — completing task #15's title objective. Every fix matches
g++ 13 AND clang++-18 on oracle-verified tests; the suite grows 796 → 798.

Highlights:

- `__is_destructible` joins the trait-builtin registry ([meta.unary.prop]),
  so libc++ 18's `#if __has_builtin(__is_destructible)` branch serves the
  trait directly — including deleted, member-deleted, and private
  destructors.
- libstdc++'s SFINAE/declval chain fixed at four layers: deleted destructors
  are recorded when dropped; explicit/pseudo destructor calls on deleted
  destructors are rejected in every context (the substitution failure inside
  SFINAE decltypes); a call-result receiver (`declval<_Tp1&>().~_Tp1()`)
  now reaches the explicit-destructor recognition; and member templates
  capture per-param DEFAULT token runs, enforced per [temp.deduct]/8 at the
  call — a failing default drops the candidate to the ellipsis catch-all.
- The forest lane can no longer bake a constant past an unenforceable
  SFINAE: a capture-time resolution that would freeze `true_type` into a
  pattern's alias node now poisons the capture, keeping the class on the
  legacy re-parse lane in every consumer. Forest format v36 carries the
  member-template default runs (pattern payload + CIR_TMPLK_MEMBER records).
- New gates: `testdestructible` + `testdestructible_libcxx`.
- Filed: deduction-aware default enforcement for the free-function lane,
  array-type template arguments, access control inside SFINAE contexts, and
  freeze carriage of the deleted-member flag family.

Suites: fulltest 798/0/0/9; `--exe` 780/0; `--obj` 780/0; packed arbiter
798/0/0/9. MIR fork unchanged (1.0-madc.0.52.0).
