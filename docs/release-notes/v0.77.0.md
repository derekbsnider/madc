# Release v0.77.0 — 2026-08-11

One repository. MIR — madc's maintained downstream of Vladimir
Makarov's MIR/c2mir, carrying the `_Complex`/cleanup/SIMD/Mach-O work
the backend depends on — now lives in-tree at `third_party/mir` as a
Git subtree with its full history preserved. `git clone` +
`./configure` + `make -C src` builds everything; there is no second
repository to clone, no pinned commit to check out, and no fork release
to pair with a madc release ever again.

- **`third_party/mir` is ordinary madc source** — a MIR-touching fix
  and the madc feature that needs it land in one commit, one branch,
  one review. The import is tree-hash-identical to the exact commit the
  final `MIR_COMMIT` pinned (fork release `v1.0-madc.0.76.0`).
- **`make -C src` builds libmir + c2m itself** — every MIR build
  product (host + cross + hosted darwin variants) lands under
  `obj/mir/<variant>`, never inside the subtree; new `mirclean` target.
- **Pin machinery retired** — `MIR_COMMIT`, `MIR_VERSION`, branch
  correspondence, and the lockstep merge/tag/release ceremony are gone;
  the madc commit IS the pin. ADR 0002 records the decision.
- **Upstream flow preserved** — `vnmakarov/mir` remains the true
  upstream (deliberate subtree pulls); `derekbsnider/mir` is frozen as
  the historical downstream and the transport for clean upstream PR
  branches (tag `madc-pre-subtree-migration` marks its final standalone
  state; in-flight PRs mir#461/#462/#463 are unaffected).
- **Migration proven behavior-neutral**: fulltest 1019/0 twice (main
  tree AND a fresh clone built with the old `/workspace/mir` renamed
  away — the stale-checkout negative control), libc++ lane 1015/0,
  EXE/OBJ 990/0, release + packed suites green, `release-macos` with
  its Mach-O gates green, MIR's own suite green (1145 tests), torture
  byte-identical to the pre-migration binary.
- Known-open, pre-existing (NOT this release): 5 torture fails
  introduced somewhere in the 2026-07-23 → 2026-08-11 window, under
  investigation (`docs/parity/failset-classification.md`).
