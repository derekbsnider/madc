# Release v0.41.0 — 2026-07-24

The ODR/linkonce weak release (ELF-completion slice 4). The C++
vague-linkage set — template instantiations, in-class/header method
bodies, vtables, typeinfo, synthesized members — is now captured as
`STB_WEAK`, so two translation units' identical copies merge at native
links instead of colliding as duplicate strong definitions. Ships
against MIR fork release `1.0-madc.0.41.0`.

## Highlights

- **Linkonce merging (gcc/ld-shaped)** — a multi-`.o` link keeps the
  first weak copy and a strong definition replaces a weak one; two TUs
  sharing an in-class method or a `vector<int>` instantiation now link
  and run in every native lane (PIE, `-no-pie`, `-shared` + dlopen,
  `-r`, run-direct merged caches).
- **External-linker parity** — madc `.o` caches carry real `STB_WEAK`
  symbols, so a gcc/ld link dedupes them natively; the g++ source
  oracle produces the same behavior.
- **Fork: binding enum, not a bit** — `MIR_item_set_binding` with
  GLOBAL / WEAK / LINKONCE. Both non-global kinds bind `STB_WEAK`;
  only interposable `__attribute__((weak))` suppresses inlining (gcc
  parity — a weak definition may be replaced at link time), while
  LINKONCE copies stay inlineable (ODR-identical), preserving JIT
  template-instantiation inlining.
- **c2mir surface** — `__attribute__((weak))` / `((linkonce))` in the
  declaration specs, with the gcc-shaped "weak declaration must be
  public" diagnostic; bindings survive binary and text MIR round trips
  (binding-less streams stay byte-identical).
- **One classification predicate** — parse-layer
  `FuncDef::vague_linkage` (in-class/deferred bodies, template
  instantiation products, system-header bodied free functions) +
  `tsubst_source`; `--emit=c11` renders the marker as portable
  `__attribute__((weak))` (warning-free under gcc).
- **Documented loud boundary** — an explicitly-`inline` USER-header
  free function still collides at link (the lexer erases `inline`);
  the follow-on slice models `inline` as a real specifier.
- **Suite state** — fulltest + packed arbiter 753/0/0/9; `--exe` and
  `--obj` lanes 737/0 each; fork object + load-object lanes 1140/2280
  ×2 (new all-lane `weak-linkonce.c` test); twelve container gates
  including external gcc/ld and g++ oracles.
