# Release v0.73.0 — 2026-08-08

The packed lane stops paying for templates it never uses. `#include
<string>` on the forest-packed binary drops from 185 ms to 124 ms
(−33 %), an unused include from 154 ms to 109 ms, and the gap to the
plain-C path narrows from 6× to 4.8× — the owner-directed latency
mission (task #25), delivered as decode-in-place, no-init decode
buffers, honest phase attribution, and lazy template thaw.

- **Lazy template thaw**: forest-restored templates (class / partial /
  alias / fn) register as identity-only stubs; payload decodes on first
  content read at the thaw owners, so a TU pays only for the templates
  it actually instantiates (`<string>`'s class-pattern deferrals:
  ~600 eager → 5 thawed).
- **Deferred free-overload recapture**: stream/manipulator/getline
  signature tables derive one-shot at the first consult, with a
  journal-snapshotted cursor so rollbacks re-derive cleanly.
- **Decode-in-place + O(1) segment lookup**: staging buffers deleted;
  one shared `decode_payload` core; indexed segment directory.
- **No-init decode destinations**: `decode_vector`/`decode_bytes` kill
  the resize zero-fill on buffers the decoder overwrites.
- **Honest phase attribution**: the depth-guarded `ForestWorkFrame`
  clock carves forest work out of lex/parse/cir in `--show-stats`.
- **New fulltest gate**: `check-template-thaw-choke.sh` — no unmarked
  direct reads of the lazy template registries.
- Batteries at the release tree: fulltest 1002/0, packed 1002/0/9skip,
  libc++ JIT 998/0/13skip, EXE/OBJ 981/0. MIR fork unchanged
  (1.0-madc.0.68.0).
