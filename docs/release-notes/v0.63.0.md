# Release v0.63.0 — 2026-07-30

The libc++ parity-lane burn-down. The flavored suite lane
(`run_tests.sh --stdlib=libc++`) went from 534 passed / 282 failed to
747 / 108 across ~50 oracle-verified fixes, with the failing set
comm-diffed at every step — zero regressions anywhere along the arc.
The string wall fell (`std::string c = a + b` runs correctly under
libc++), and four flavor-independent silent-wrong-answer bugs the lane
exposed are fixed for every dialect.

Highlights:

- The stdlib-flavor parity lane is first-class: the whole suite runs
  under `-stdlib=libc++`, the failing set is banked in
  `docs/parity/libcxx-failset.txt`, and EXE/OBJ failures gate the exit.
- `using X = U*` alias targets keep their declarator suffix — every
  pointer-target alias template was silently de-pointered before.
- A ctor-less class copy-constructs from its argument; the by-value
  call-receiver spill temp was silently uninitialized.
- An empty non-primary base lays out at Itanium offset 0 (EBO) —
  libc++'s `__compressed_pair` read one-past-the-object before.
- `--emit=c11` renders bit-field widths.
- `std::string` operator+ end-to-end under libc++: by-value class
  operator results materialize like call results; friend-specialization
  operator declarators parse; the JIT loads the active flavor's runtime.
- Ref-qualified member functions ([dcl.fct]p6), east-cv template
  arguments, and operator-> rewrites on member/call-result receivers.
- Out-of-line definitions bind by signature, not first-available
  overload; explicit specializations' out-of-line ctors/dtors parse.
- A name after `.`/`->` resolves as a member, never a type
  ([basic.lookup.classref]).
- MIR fork release `1.0-madc.0.63.0`: zero-length arrays match
  gcc/clang diagnostics (silent by default, `-pedantic` warns).

Suites: fulltest 856/0; parity lane 747/108 and burning down.
