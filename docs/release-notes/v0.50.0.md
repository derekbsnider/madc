# Release v0.50.0 — 2026-07-26

Forest carriers **S5**: `madc -static-libmadc -o prog prog.c` now carries the
madc runtime pieces a program actually uses *inside* the emitted image, so the
binary runs on a machine with no madc installed. The pieces come from a new
**AOT ledger** — madc's C-lane runtime, turned into dual-build C11 sources that
the host build compiles into libmadc and that **madc itself compiles through
c2mir** into MIR modules carried in its frozen-forest container. On Mach-O,
where no madc library exists at all, this is what makes a `try`/`catch` program
emittable in the first place.

- **`-static-libmadc`** (alias `-static`, per gcc's `-static-libgcc`): the
  emitted image carries the runtime; libc and libstdc++ stay dynamic, so the
  flag promises exactly what its name says.
- **The ledger is one implementation, two consumers.** `src/rt/rt_except.c`
  (the whole SJLJ try/throw/catch + cleanup runtime) and `src/rt/rt_vla.c` are
  compiled into libmadc by the host build *and* into MIR ledger modules by madc
  at pack time. `scripts/ledger_sources.txt` is the single owner of the list.
- **It rides the carriers you already have.** The ledger is a new optional
  forest-container segment, so it reaches the self-image, the libmadc image,
  the sidecars and `$MADC_FOREST` for free — but is read independently of the
  grove bind, because madc's own runtime is target-specific and
  dialect-agnostic (a `--std=c99` compile still links it).
- **Two honest refusals, never conflated.** "This madc ships no ledger" points
  at the build (use a packed/installed madc, or `--forest-bind=<file>`);
  a Tier-B program — one needing the C++ script-lane runtime — is refused with
  the offending symbols listed.
- **Two cover-analysis bugs fixed**, both of which had been forcing needless
  `libmadc.so.0` dependencies: copy-relocated libc data (`stderr` lives in
  `bin/madc`'s own `.bss`, so it looked uncovered), and host-vs-target symbol
  probing on cross builds (darwin's `__stderrp` does not exist in glibc).
- **Gated** by `scripts/forest_ledger_gate.sh` in `fulltest` — 14 checks,
  including a baseline leg per program so the `-static-libmadc` legs cannot
  pass vacuously, and a run under an empty library path.
- **Validation:** fulltest 756/0/0/9, `--exe` 740/0, packed arbiter 756/0/0/9.
  The packed `bin/madc-release` (240 units + 2 ledger modules) emits a
  try/catch program with zero `libmadc` DT_NEEDED entries that runs under
  `env -i LD_LIBRARY_PATH=/nonexistent`. Cross-emitted from Linux, both Apple
  arches produce a valid Mach-O executable with no libmadc reference and no
  undefined `__madc_*` symbols; running one still needs Apple hardware.
- **Known boundaries:** the `.o` link lane refuses `-static-libmadc` (it merges
  native relocatables, which needs the fork's MH_OBJECT flavor), and a
  `-static-libmadc` image carries process-global rather than per-thread
  exception state because MIR has no thread-local storage.
- MIR fork unchanged (`1.0-madc.0.47.0`).
