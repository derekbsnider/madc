# std:: Types as Real Classes (retire the C++ shortcut artifacts) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire madc's legacy C++ shortcut artifacts (`dtSTRING` special-case lowering, the `tkSTRING` type token, the `tkVECTOR`/`tkMAP`/`tkSET`/`tkLIST` keywords, `ns_stl.cpp` wrappers) and model `std::string` / `std::vector<T>` / `std::map<K,V>` / `std::set<T>` as ordinary `std::`-namespaced C++ class/template types **defined by `#include <string>` / `<vector>` / `<map>` / `<set>`** — flowing through madc's real C++ framework (class model + mangled-direct libstdc++ + template instantiation), so `vector<string>` and every future `std::` container work with zero type-specific machinery.

**Architecture:** These types were builtins only because a proper C++ framework didn't exist; it does now. `std::string` is *already* a `DataDefCLASS` (`typedef DataDefCLASS DDClass;` in `include/datadef.h:659`, and `class DataDefSTRING : public DDClass`). We make the cir_builder treat it *as* a class: its methods/ctor/dtor/operators are class methods whose **emit symbol is the mangled libstdc++ name** (generated by `src/madc_mangle.*`), reached through the existing `class_method_call` (which emits `tm->var.name` as the call symbol, `src/cir_builder.cpp`). Containers become real madc-dialect templates in `include/madc/vector|map|set`, instantiated per use (the engine landed earlier this session). All four types are registered **lazily on `#include`** (the `embedded-headers.md` mechanism) under `std::` only — no global `string`/`vector`, no hardcoded tokens. Every `dtSTRING` special path and `ns_stl` is deleted as the class/template path takes over.

**Tech Stack:** C++11; madc parser (`src/parser.cpp`), lexer (`src/lexer.cpp`), cir_builder (`src/cir_builder.cpp/.h`), mangler (`src/madc_mangle.*`); c2mir node API; the madc MIR fork at `/workspace/mir`; doctest unit tests; `.mad` integration tests; `make -C src fulltest`; g++/clang as the parity reference (Rule #1).

**Baseline:** **372** integration tests passing on `feature/cir-stdstring-claude` (the earlier "371" was off-by-one; the flaky `testfortypedcomma` flips fail↔timeout — ignore only that). Every task must keep 372 green; never trade a passing test for a failing one.

- [ ] **Step 1: Decide the method-symbol-override mechanism (investigation, document inline)**

`class_method_call` emits `tm->var.name` as the call symbol. Two ways to make a string method call a mangled libstdc++ symbol:
  - (a) Set each string-method `Variable.name` to the mangled symbol at registration (so `tm->var.name` IS the mangled symbol). Cleanest; reuses `class_method_call` unchanged. BUT the *parser* resolves `s.length()` to the method Variable by unmangled name (`method_map["length"]`), so the lookup key must stay `length` while the emit name is the mangled symbol.
  - (b) Add an optional `std::string emit_symbol` to `FuncDef` (empty = use the default `ClassName__method`); `class_method_call` uses `callee->emit_symbol` when set.

  Choose **(b)** — it keeps parser lookup (`length`) and emit symbol (mangled) cleanly separate and generalizes to any externally-defined class (future `std::` types). Verify `FuncDef` is reachable from `tm->var.type` in `class_method_call` (it is: `FuncDef *callee = dynamic_cast<FuncDef *>(tm->var.type)`).

```c
// madc embedded <vector> — std::vector<T> as a real madc template.
#include <stdlib.h>
namespace std {
template<typename T> class vector {
    T* data;
    long len;
    long cap;
    vector() { data = (T*)malloc(4 * sizeof(T)); len = 0; cap = 4; }
    ~vector() { free(data); }                 // (element dtors: Task B3)
    void push_back(T v) {
        if (len >= cap) { cap = cap * 2; data = (T*)realloc(data, cap * sizeof(T)); }
        T* slot = data + len;                 // pointer arith (NOT &data[len])
        new (slot) T(v);                       // placement copy-construct
        len = len + 1;
    }
    T& operator[](long i) { return data[i]; }
    long size() { return len; }
};
}
```
