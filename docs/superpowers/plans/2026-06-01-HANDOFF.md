## 0. THE VISION (why any of this exists) — never drift from this

madc = "My Advanced Dialect of C". The long arc (see `docs/plans/madc-vision-and-invariants.md`,
invariants **I1–I8**, the gate every change must pass):

- madc is a **polyglot transpiler**. One pipeline reads a source language/standard X and emits
  a target Y, through a SINGLE intermediate representation: the **`cir_node` tree (MC11-IR)**.
- Why a C/C++ AST is the universal substrate: **most languages are themselves implemented in
  C/C++**, so a faithful C/C++ AST is their common denominator. C is the floor; C++ lowers to
  C11 (Cfront-style).
- **Borrowed-language features (`php::`/`perl::`/`python::`/`ruby::`/`js::`) are reimplemented
  NATIVELY in libmadc** — they are NOT calls into those languages' runtimes. (Linking real
  foreign runtimes may come later, but the conventions themselves are native C/C++ libraries.)
- The **`--std=` / `LanguageStd` enum is the dialect gatekeeper on BOTH ends**: (a) INPUT — which
  keywords/features are legal (so C and C++ dialects don't clash); (b) OUTPUT — the c2mir target
  standard is driven by this enum, NOT hardcoded to C11 (c2mir may someday do C17/C23). Same enum
  enables standard-to-standard conversion. Default `--std=madc`. This is partly wired
  (lexer ~1309-1339); the full keyword/feature→standard REGISTRY is roadmap P2.11 (the keystone).
- Concrete proving ground: **SMAUG 1.8** (~158k LOC C89) must compile AND run. The port lives in
  the separate **MadSMAUG** repo (symlinked at `/workspace/madc/MadSMAUG`). It currently **boots
  end-to-end AND passes a serpent-room combat run** through madc.

Invariants (I1–I8, paraphrased): one IR (dual-view); C/C++ floor; the std-enum on both ends, never
hardcoded; every feature gated via a keyword/feature→standard registry; one emitter; no
special-casing; borrowing-native-in-libmadc; honest gating. **Before any change, ask: "does this
block the vision?"**

## 1. HOW `cir_node` WORKS (the IR — SET IN STONE; read `.claude/rules/mc11-ir.md`)

The pipeline is **`madc parser → cir_node tree (MC11-IR) → c2mir → MIR → JIT`**. It is the SOLE
backend (asmjit and the Gecko experiment were removed). Key facts:

- **`cir_node` DERIVES FROM c2mir's `struct node` (node_t)** — `base` is at offset 0, so a
  `cir_node*` IS-A `node_t*` that c2mir's checker/generator process normally. madc owns the node
  memory (an arena). Defined in `src/cir_node.h`; built by class **`CirBuilder`** in
  `src/cir_builder.cpp` (helpers: `node1/node2/node3`, `list`, `append`, `id`, `str`, `integer`,
  `simple`; leaf/decl/stmt/expr builders; `translate_expr`/`translate_stmt`/`translate_block`/
  `translate_module`).
- **It is DUAL-VIEW by construction** (never re-pose "lowered OR high-level" — it is BOTH):
  c2mir consumes the lowered C11 `node_t` view; madc retains the high-level view because every
  `cir_node` also carries its originating `TokenBase`/parse subtree + file:line:col (`->origin`,
  positions). Reverse-rendering reads those, never reconstructs from comments.
- **The tree is fed DIRECTLY to c2mir** via `c2mir_compile_tree` (in `src/madc_cir.cpp`,
  `madc_cir_execute` → checker → `MIR_gen`). **There is NO emitted-C step in the live pipeline.**
- **`src/cir_emit_c.cpp` (`--emit=c11`) is a SEPARATE RENDERER**, an OUTPUT (portable C / AOT via
  gcc-clang / the cir-fidelity gate) — c2mir NEVER sees that text. The file has a big header
  comment saying so. **Debugging rule: to see what the backend actually receives, use
  `bin/madc --dump-cir FILE.mad` / `--dump-cir-checked` — NOT `--emit=c11`+gcc.** (A whole
  session was lost once by confusing the emit-C oracle for the pipeline. The tell: if a bug
  reproduces only via emit-C+gcc but not via the tree, you're testing the renderer.)
- **Mechanics learned the hard way (2026-06-01):** c2mir lays out auto-locals into a per-function
  `alloca` frame in `process_func_decls_for_allocation`. It expects **a nested scope's `node_scope`
  uid to be LARGER than its parent's** (true for c2mir's own recursive-descent text parser, which
  creates outer scopes first). But **CirBuilder builds the tree BOTTOM-UP** (children allocated/
  uid'd before the `N_BLOCK` that wraps them), so a nested block gets a SMALLER uid than its
  parent. The FIX (fork `01f999b`) made c2mir order by ACTUAL scope depth, not uid — robust for any
  externally-built tree (serves the vision). Lesson: c2mir's internal "uid reflects nesting"
  assumptions don't hold for externally-built trees; prefer fixing c2mir to use authoritative
  structure (the scope chain) over making cir_builder mimic the parser's incidental ordering.
- Adding support for a construct = add a `translate_*` case in cir_builder mapping the madc token
  to the right c2mir node (e.g. compound literal → `N_COMPOUND_LITERAL`; `__real__` → `N_REALPART`;
  `&&label` → `N_LABEL_ADDR`; `goto *e` → `N_INDIRECT_GOTO`). The c2mir node codes are in
  `/workspace/mir/c2mir/c2mir_node_code.h`. Reuse existing machinery (init-lists, declarator
  pieces, the class model) — never add a parallel path. Fix at the deepest correct layer.

**Where to fix a missing feature** (`.claude/rules/lowering-vs-raising.md`): Tier-1 = lower/resolve
in madc (DEFAULT — madc owns the front end); Tier-2 = raise c2mir (fork) only for genuine
semantic primitives with no faithful C11 form (precedent: native `_Complex`); Tier-3 = raise MIR
(the floor) — today only SIMD/vectors and **VLAs** (c2mir has NO variable-length-array support).

  Agent tool; or continue a prior one via SendMessage to reuse its context). Brief them LIBERALLY:
  the architecture (esp. "tree is the backend, emit-C is NOT"), exact file anchors, the gate
  baseline, gcc-canon, "don't shim / fix deepest layer", and an escape hatch (report
  BLOCKED/DONE_WITH_CONCERNS). They do the integration gate; the COORDINATOR owns the SMAUG check.
- **Coordinator VERIFIES every subagent result — NEVER relay a claimed "done":** re-build, re-run
  `make -C src fulltest`, diff the failset vs baseline (must add nothing), run the target tests,
  and SMAUG-soak when the change touches codegen/emission ordering. (This caught the typedef→SMAUG
  regression that the test suite missed — #3 above.)
- **gcc/clang are canon.** Compare via `gcc -O0` on the equivalent `.c` (strip `#!` shebang:
  `tail -n +2 x.mad > tmp/x.c`). Inspect the real tree with `--dump-cir`, never emit-C+gcc.
- **SMAUG soak (foreground, tmpfs-safe):**
  `cd /workspace/MadSMAUG/runtime/area; timeout 50 /workspace/madc/bin/madc /workspace/MadSMAUG/src/SMAUG.mad 4000 > /workspace/madc/tmp/x.log 2>&1`
  — exit **124 = survived = good**; then grep the log for `ready at` / `SIGSEGV|SIGBUS|[JIT]`.
  **Serpent combat run** (the real gameplay test, for command-dispatch/broad changes):
  `bash /workspace/madc/tmp/run_serpent2.sh` (starts server bg, runs `tmp/serpent_full.py` client,
  ALL output to repo `tmp/`; `SERVER_ALIVE_AFTER_PLAY` + combat lines = pass). Kill stray servers
